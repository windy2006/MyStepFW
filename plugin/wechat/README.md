# 微信网页功能（wechat） <small>v1.0.0</small>

## 功能概述

本插件让网站在微信内打开时使用微信JS-SDK，例如分享封面、扫一扫、拍照、录音和定位。网站仍由MyStepFW运行，微信提供网页可调用的能力。

普通浏览器不注入。链接从公众号菜单、聊天或二维码进入微信内置浏览器均可；不要求访客已经关注公众号。插件不负责微信登录、自动回复、群发或支付订单创建。

在安装／设置页点击按钮区的“插件说明”阅读本文件；设置项名称下方的“填写说明”定位到对应章节。链接遵循框架当前路由模式，阅读不要求插件已安装、启用或登录后台。

## 安装与设置

准备一个可用的公众号及一个HTTPS网站。以下用 `https://cms.example.com` 举例，实际填写时必须换成自己的域名。

1. 登录微信公众平台／微信开发者平台，确认账号实际为订阅号还是服务号，以及是否已经通过微信认证。不要根据自己想使用的功能选择账号类型。
2. 在账号的开发信息／基本配置中取得AppID与AppSecret。菜单名称可能随平台调整，以账号后台实际界面为准。
3. 找到“IP白名单”，加入网站服务器调用微信接口时使用的公网出口IP。它通常由主机商或运维提供；不是访客IP，也不一定是域名解析IP。
4. 找到“JS接口安全域名”，填写网站域名，例如 `cms.example.com`。若微信要求上传校验文件，将它放在网站可访问的位置，并按微信页面提示完成验证。域名备案等要求以微信后台校验为准。
5. 在MyStepFW框架后台打开“插件管理 → 微信网页功能”，安装、启用插件，勾选需要生效的前台应用，例如CMS。不要为了方便绑定所有应用。
6. 进入插件设置，先参考[最小配置示例](#常用配置方案)，填账号、密钥、允许来源和接口，最后将“启用网页功能”设为“开启”并保存。后台会先测试微信API，测试通过才保存开启状态；失败时本次修改不保存。
7. 把网站链接发送到手机微信，点击打开。首先测试“扫一扫”，再增加分享、定位或业务脚本。

安装、插件启用、应用绑定和本插件的“启用网页功能”是四个独立条件，缺一都不会生效。安装不会自动开通微信权限，也不会将网站会员与微信身份绑定。

## 设置说明

以下项目在插件参数设置页面维护，保存后按应用绑定生效。

### setting-enabled

**启用网页功能**（`enabled`）

**填写方式：**选择“开启”或“关闭”，初始为“关闭”。

- 第一次填写账号期间保持关闭，可以先保存草稿。配齐AppID、AppSecret、允许来源及至少一个符合账号条件的接口后，再选“开启”并保存。
- 保存开启设置时，服务器会重新调用微信stable_token和jsapi_ticket接口测试；即使已有未过期票据，也不会跳过测试。通过后才保存并生效。
- 测试失败时拒绝保存整批修改，原来的配置及启用状态保持不变；请修正信息后再保存。若原来已经开启、现在希望暂停，请先选择关闭并保存。
- 开启期间保存设置也会重新测试，修改账号信息无法沿用旧账号的测试结果。关闭状态保存草稿不会调用微信。
- 开启表示允许本插件为已绑定的前台应用提供网页功能；框架插件管理里的启用状态也必须打开。
- 关闭后不再注入SDK或提供本插件的签名动作；已保存的配置保留。

**示例：**准备阶段选“关闭”；完成账号、允许接口、微信后台域名和白名单设置后选“开启”并保存。凭据错误、IP不在白名单、网络异常或票据接口失败时，均不能保存开启设置。

**测试范围：**服务器测试确认凭据、网络及JS-SDK票据获取成功，不代表所选的每个JS接口均已获准，也不能验证微信内当前页面的安全域名、客户端支持或用户授权。这些仍需保存成功后在手机微信内验证。

### setting-account_type

**账号类型**（`account_type`）

**填写方式：**按微信账号后台实际显示选择“订阅号”或“服务号”。不能填写微信小程序、开放平台网站应用或企业微信的AppID来替代。

**示例：**内容发布使用的订阅号选“订阅号”；已经注册为服务号的业务账号选“服务号”。

它影响可申请的接口：本插件只向已认证服务号开放支付SDK入口；已认证订阅号可以配置分享和符合条件的卡券接口，但不能通过把此项改为“服务号”取得支付权限。完整对照见[账号能力](#服务号与订阅号能力判断)。

### setting-verified

**微信认证**（`verified`）

**填写方式：**微信账号已经通过有效的微信认证时选“是”，其余选“否”。普通注册成功、管理员实名认证或填写了主体资料，不应直接当成已经通过微信认证。

**示例：**账号后台显示已完成微信认证，选“是”；个人订阅号没有相应认证资格，选“否”。

未认证账号仍可按微信权限表申请基础、图像、语音、位置、扫一扫等接口；本插件会过滤分享定制、卡券和支付。认证状态由管理员据实维护，测试不会自动查询或更改认证状态；真实权限最终由微信裁决。

### setting-appid

**应用ID**（`appid`）

**在哪里取得：**微信账号后台的开发信息／基本配置中，通常显示为“开发者ID（AppID）”。AppID必须属于本页选择的那个公众号。

**格式：**以 `wx` 开头，后接16个字母或数字，共18个字符。不要带空格、引号或参数名称。

```text
wx1234567890abcdef
```

以上是格式示例，不能直接使用。不要把微信原始ID（常见为 `gh_…`）、商户号、管理员微信号、AppSecret填到这里。网页功能开启时必填；AppID会作为公开的SDK配置出现在网页里，密钥不会。

### setting-secret

**应用密钥**（`secret`）

**在哪里取得：**同一公众号的开发信息／基本配置中显示的开发者密码（AppSecret）。若后台只支持重置，请先了解这个公众号是否还被其他系统使用，重置会影响已有接入。

**填写方式：**第一次在“应用密钥”和“重复密钥”两个输入框粘贴相同的真实密钥；不要添加引号。当前插件接受16至128个英文字母或数字，实际值以微信给出的为准。

```text
应用密钥：粘贴微信后台给出的完整密钥
重复密钥：再次粘贴同一个密钥
```

保存后密码框不回显原文。再次编辑其他设置时，两个框都留空即可保留已有密钥；留空不是清除密钥。开启网页功能时必须已有有效密钥。不要把密钥写入HTML、初始化脚本、分享链接或截图。

还必须在微信后台配置**服务器公网出口IP白名单**，否则即使密钥填写正确，服务器也可能无法取得票据。AppSecret与JS-SDK的签名、access_token、jsapi_ticket是不同内容，不能互填。

### setting-origins

**网站来源**（`origins`）

**作用：**限制本插件允许为哪些网站来源签名。每行填写一个精确的HTTPS来源，包含协议与域名，不含末尾斜杠、路径、端口、查询串或通配符。推荐使用小写域名。

```text
https://cms.example.com
https://www.example.com
```

**对照填写：**

| 位置 | 应填内容 | 含义 |
| --- | --- | --- |
| 本插件“网站来源” | `https://cms.example.com` | 网站实际访问来源 |
| 微信后台“JS接口安全域名” | `cms.example.com` | 按微信要求填写域名并完成校验 |
| 用户实际打开的网址 | `https://cms.example.com/news/123?from=menu` | 具体业务页面 |

**错误示例：**`cms.example.com`（缺协议）、`http://cms.example.com`（非HTTPS）、`https://cms.example.com/`（带路径斜杠）、`https://cms.example.com:8443`（带端口）、`https://*.example.com`（通配符）。IP地址也不支持。

`https://example.com` 和 `https://www.example.com` 是不同来源；要使用两个域名就分别填写，并完成微信侧的域名配置。本插件不会因为微信允许父域名而自动允许所有子域名。开启网页功能时至少填写一个来源，测试域名也须遵循相同要求。

### setting-exclude_paths

**排除路径前缀**（`exclude_paths`）

**作用：**让指定页面不注入微信内容，也不为这些页面提供签名。每行一个以 `/` 开始的URL路径前缀，不填协议、域名、查询串或 `#`。区分大小写，不支持通配符。

```text
/Admin/
/admin_cms/
/user/security/
/payment/private/
```

例如 `/user/security/` 会排除其下的 `/user/security/password/`。它不会匹配 `/User/security/`，也不会匹配没有末尾斜杠的 `/user/security`；如两种地址都存在，可分别填写。前缀 `/user` 也会匹配 `/users`，因此应尽量使用完整目录边界。

初始示例为 `/Admin/`、`/admin/`、`/myStep/`。插件还会自动跳过框架Admin／myStep应用以及宿主应用声明的后台路径，但自定义敏感页面仍应按网站实际地址填写。

可以留空，表示不额外排除前台路径；填写单独的 `/` 会匹配所有页面，通常会导致整个网站都无法使用本插件。

### setting-apis

**允许接口**（`apis`）

**作用：**声明网站准备使用的接口。用英文逗号、空格或换行分隔，拼写及大小写必须与接口名完全一致。不要填写中文功能名称、括号、`wx.`前缀或JSON数组。

**基础体验示例：**

```text
checkJsApi,chooseImage,previewImage,scanQRCode,getLocation,openLocation
```

**已认证账号的分享示例：**

```text
checkJsApi,updateAppMessageShareData,updateTimelineShareData,scanQRCode
```

只填写准备使用的接口。留空时没有业务接口被允许，快捷按钮也不会显示功能。未知接口或已弃用的旧分享接口会被拒绝保存；本插件支持但当前账号不符合条件的接口会被过滤，不代表保存失败。

**所有支持接口及用途：**

| 分类 | 接口名称 | 可以做什么／额外说明 |
| --- | --- | --- |
| 检测 | `checkJsApi` | 检测当前微信客户端支持情况；插件也会自动进行能力检测 |
| 分享给朋友 | `updateAppMessageShareData` | 设置分享标题、简介、图片和链接 |
| 分享到朋友圈 | `updateTimelineShareData` | 设置朋友圈分享标题、图片和链接 |
| 图片选择／预览 | `chooseImage`、`previewImage` | 拍照、相册选图，以及预览给定图片URL |
| 图片传输 | `uploadImage`、`downloadImage`、`getLocalImgData` | 与微信媒体服务交互、取得本地图片数据；上传不等于已保存网站附件 |
| 录音 | `startRecord`、`stopRecord`、`onVoiceRecordEnd` | 开始、停止、监听录音结束 |
| 语音播放 | `playVoice`、`pauseVoice`、`stopVoice`、`onVoicePlayEnd` | 播放本地语音及监听播放结束 |
| 语音传输／识别 | `uploadVoice`、`downloadVoice`、`translateVoice` | 上传下载语音、语音转文字；需业务应用接收结果 |
| 网络 | `getNetworkType` | 获取当前网络类型 |
| 位置 | `getLocation`、`openLocation` | 获取位置、用微信地图查看给定位置 |
| 页面关闭 | `closeWindow` | 关闭当前微信网页窗口 |
| 菜单 | `hideMenuItems`、`showMenuItems`、`hideAllNonBaseMenuItem`、`showAllNonBaseMenuItem` | 控制微信页面菜单项 |
| 扫码 | `scanQRCode` | 调起微信扫一扫；可接收扫码结果 |
| 卡券 | `chooseCard`、`addCard`、`openCard` | 选择、加入和查看卡券，受专项条件限制 |
| 支付 | `chooseWXPay` | 拉起支付，受专项条件限制；需要业务服务器生成订单与参数 |

填写接口只允许调用它，不会自动完成业务。除分享设置及可选快捷按钮外，还需在[初始化脚本](#setting-ready_script)或应用代码中调用。拍照、扫码、录音、定位等能力应由用户点击触发。

### setting-card_enabled

**已开通卡券**（`card_enabled`）

**填写方式：**只有实际账号已经具备相应卡券能力、网站也准备调用时才选“是”；没有卡券业务或无法确认时选“否”。默认“否”。

**示例：**已认证订阅号具备卡券权限，网站已经有领取优惠券业务，可以选“是”，并将需要的 `addCard`／`openCard` 等加入接口列表。

生效须同时满足：微信认证、此开关开启、接口加入允许列表、微信侧实际权限及业务参数有效。卡券签名与JS-SDK签名不同，本插件不会创建优惠券、生成卡券专用签名或自动核销。只开启开关不会出现领券按钮。

### setting-pay_enabled

**微信支付**（`pay_enabled`）

**填写方式：**只有已认证服务号完成微信支付相关接入，网站支付业务也已实现时选“是”。订阅号、未认证服务号以及尚未接入支付的网站选“否”。默认“否”。

**示例：**已认证服务号已关联适用商户号，业务服务器能够创建支付订单并返回支付参数，此项选“是”，允许接口加入 `chooseWXPay`。

这个开关只控制能否申请SDK支付接口，不是“开通微信支付”按钮。它不会创建商户、下单、生成支付签名、收款或退款。业务服务器仍须核对微信支付通知及订单状态，不能只根据网页成功回调确认到账。

### setting-share_title

**分享标题**（`share_title`）

**填写方式：**填写想在分享卡片上显示的标题，最多200个字符；可以留空。需已认证账号，并在接口列表加入相应分享接口。

```text
春季新品预约 · 示例商城
```

留空时使用当前页面的 `document.title`，适合新闻、商品等各页标题不同的网站。填写固定值会让所有生效页面使用同一标题；若希望每个商品使用自己的名称，通常应留空。

`updateAppMessageShareData` 用于分享给朋友，`updateTimelineShareData` 用于朋友圈；两者都需要就都加入。设置成功只表示配置了分享内容，不能证明用户已经分享，也不应作为发奖依据。

### setting-share_desc

**分享简介**（`share_desc`）

**填写方式：**填写分享给朋友时的简短介绍，也可以留空。

```text
查看商品详情、预约到店体验，并了解最新活动。
```

留空时读取当前页面的 `<meta name="description">`，页面没有该标签时简介为空。朋友圈分享通常没有与聊天卡片相同的简介展示，不要依赖它展示关键业务信息。

页面动态简介示例（这是应用页面HTML，不填写在本字段）：

```html
<meta name="description" content="本页商品的具体介绍">
```

### setting-share_image

**分享封面**（`share_image`）

**填写方式：**填写可公开访问的完整HTTPS图片地址，也可以留空。不要填服务器磁盘路径、相对地址、网页文章地址或需要登录才能查看的图片。

```text
https://cms.example.com/static/images/share-cover.jpg
```

留空时读取当前页面 `<meta property="og:image">` 的内容；若也没有，则不提供封面地址。图片应允许微信抓取，不能被登录、防盗链或失效临时链接阻挡，建议准备清晰的方形封面并用真机确认展示效果。

每页不同封面的HTML示例：

```html
<meta property="og:image" content="https://cms.example.com/images/product-123.jpg">
```

本插件不会代为上传图片，也不会验证图片是否真的可下载。

### setting-toolbar

**显示快捷按钮**（`toolbar`）

**填写方式：**需要插件自动生成基础操作按钮时选“显示”，已有自己的页面按钮或暂不需要时选“隐藏”。默认“隐藏”。

| 自动按钮 | 必须允许的接口 | 点击后的结果 |
| --- | --- | --- |
| 扫一扫 | `scanQRCode` | 触发 `mystep:wechat-scan` 事件，包含扫码结果 |
| 拍照／选图 | `chooseImage` | 触发 `mystep:wechat-image` 事件，包含本地图片标识 |
| 获取位置 | `getLocation` | 触发 `mystep:wechat-location` 事件，包含坐标等结果 |

按钮放在页面body末尾的微信内容区域。只有接口已经允许、账号校验成功、客户端支持时才显示；不会在页面打开时自动请求相机或位置权限。

**示例：**第一次接入时选“显示”，接口填基础体验示例，先核对能否正常调起微信功能。结果要显示到业务页面或提交网站后台，仍需应用监听事件处理，见[完整调用示例](#浏览器对象事件和spa)。

### setting-html

**专属内容**（`html`）

**填写方式：**可填写仅在微信内页面显示的HTML，不需要增加html、head或body外壳；没有专属内容时留空。内容会放在页面body末尾，不替换原页面，也不会执行PHP。

可与下一项初始化脚本配套的示例：

```html
<section aria-label="微信扫码查询">
    <p>点击按钮扫描业务二维码，结果会显示在下方。</p>
    <button id="my-scan-button" type="button">扫描业务二维码</button>
    <output id="scan-result" aria-live="polite"></output>
</section>
```

只复制代码块内的HTML，不复制Markdown的三反引号。ID不要与原页面元素重复。普通文字、提示和按钮可以直接写；按钮的微信动作在“初始化脚本”中绑定。

这是管理员受信内容，不是访客留言编辑器。不要拼接未转义的访客输入或粘贴来源不明的脚本。整页框架后台和排除路径不会注入这些内容。

### setting-ready_script

**初始化脚本**（`ready_script`）

**填写方式：**填写JavaScript函数体，不填写 `<script>` 标签、Markdown围栏或PHP。没有自定义业务时留空，内置分享与快捷按钮仍可工作。

插件会在微信SDK初始化及客户端能力检测成功后运行该脚本，提供两个变量：`wx`为微信SDK，`wechat`为本插件的浏览器对象。建议通过 `wechat.call()` 调用已允许且客户端支持的接口。

与上一项HTML对应的可复制示例：

```javascript
const button = document.getElementById('my-scan-button');
const output = document.getElementById('scan-result');
if (button && output) {
    button.disabled = !wechat.supported.scanQRCode;
    button.onclick = function () {
        wechat.call('scanQRCode', {
            needResult: 1,
            scanType: ['qrCode', 'barCode'],
            success: function (result) {
                output.textContent = result.resultStr;
            },
            cancel: function () {
                output.textContent = '已取消扫码。';
            },
            fail: function () {
                output.textContent = '扫码失败，请稍后重试。';
            }
        });
    };
}
```

还须在允许接口中加入 `scanQRCode`。这里使用 `onclick` 赋值，SPA重新初始化时不会重复叠加点击监听。用户点击后才调起扫码，不要在初始化阶段直接打开相机、录音或定位。

脚本不应包含AppSecret、access_token或ticket。执行异常会触发 `mystep:wechat-script-error`，微信初始化失败则不会执行本脚本。不要把整段第三方网页代码直接粘贴进来。

## 常用配置方案

### 方案一：先跑通扫码和拍照

| 项目 | 填写示例 |
| --- | --- |
| 账号类型、认证状态 | 按账号后台实际情况选择 |
| AppID、AppSecret | 真实公众号凭据，不能使用本文示例值 |
| 允许来源 | `https://cms.example.com`，替换为实际域名 |
| 允许接口 | `checkJsApi,scanQRCode,chooseImage,previewImage` |
| 卡券、支付 | 均选“否” |
| 快捷按钮 | “显示” |
| 分享标题、简介、封面 | 暂时留空 |
| 微信专属内容、初始化脚本 | 暂时留空 |
| 启用网页功能 | 最后选择“开启” |

同时完成微信后台JS接口安全域名和服务器出口IP白名单配置，再在手机微信内打开已绑定应用的页面。

### 方案二：每篇文章使用自己的分享卡片

使用有分享权限的已认证账号，接口加入：

```text
checkJsApi,updateAppMessageShareData,updateTimelineShareData
```

分享标题、简介和封面均留空，在应用每个页面输出自己的title、description和og:image。无需填写自定义初始化脚本。分享链接默认取当前页面地址并去掉 `#` 片段；不要把敏感信息放进网址参数。

### 方案三：自定义扫码查询区

允许接口加入 `scanQRCode`，隐藏快捷按钮，分别复制[微信专属内容](#setting-html)和[初始化脚本](#setting-ready_script)中的两个代码块。它会在微信内显示扫码按钮，并把扫码结果作为纯文本展示。接入实际订单、设备查询时，由业务应用校验二维码内容并执行查询。

## 服务号与订阅号能力判断

实际可调用能力依次通过三层筛选：管理员接口列表与账号条件取交集 → 微信 `wx.config` 校验真实权限 → `wx.checkJsApi` 检测客户端支持。手工填写“已认证”或打开专项开关不会增加微信账号权限。保存开启设置必须先通过服务器凭据与票据测试，但该测试不代替客户端的接口权限校验。

| 接口组 | 未认证订阅号／服务号 | 已认证订阅号 | 已认证服务号 |
| --- | --- | --- | --- |
| 基础、图片、音频、语音识别、网络、位置、界面、扫一扫 | 按官方权限表申请 | 可申请 | 可申请 |
| 分享内容定制 | 不申请 | 可申请 | 可申请 |
| 卡券 | 不申请 | 还需卡券专项开关和真实权限 | 还需卡券专项开关和真实权限 |
| 微信支付 | 不申请 | 不申请 | 还需支付专项开关和真实接入 |

接口可用性还受微信版本、操作系统和用户授权影响。本文讲的是本插件提供的JS-SDK能力；网页OAuth、开放标签和公众号服务端消息能力不能从这个表推导。

## 浏览器对象、事件和SPA

`window.MyStepWechat`提供：

| 成员 | 用途 |
| --- | --- |
| `status` | `loading`初始化中、`ready`可以使用、`error`初始化失败 |
| `apis` | 经本插件账号条件筛选后的申请接口 |
| `supported` | 当前客户端接口支持情况，以接口名称为键 |
| `call(name, parameters)` | 调用已经允许且客户端支持的接口，否则抛出错误 |
| `refresh()` | 地址变化或特殊前端路由完成后，显式重新获取签名及初始化 |

应用可以监听以下事件。监听代码可以放在应用正常JS文件中；若放在“初始化脚本”中，则监听后续的扫码、选图等事件，不要等到初始化脚本执行后才监听本次ready。

```javascript
window.addEventListener('mystep:wechat-ready', function (event) {
    console.log('可用能力', event.detail.supported);
});
window.addEventListener('mystep:wechat-scan', function (event) {
    const output = document.getElementById('scan-result');
    if (output) output.textContent = event.detail.resultStr;
});
```

快捷按钮返回结果的事件为 `mystep:wechat-scan`、`mystep:wechat-image`、`mystep:wechat-location`。初始化失败事件为 `mystep:wechat-error`，管理员脚本异常事件为 `mystep:wechat-script-error`。图片、语音上传返回微信媒体ID时，业务服务器还需自行下载保存；不会自动成为本站附件。

插件监听history的pushState／replaceState和popstate，在地址变化后重新签名。特殊前端路由可以显式调用refresh。签名使用当前完整URL，保留查询串原始顺序和编码，剥离 `#` 片段；SPA应按当前页面内容更新自己的分享信息。

## 常见问题排查

| 现象 | 优先检查 |
| --- | --- |
| README链接返回404 | 从后台安装／设置页的“插件使用说明”进入统一插件guide，参数为idx=wechat；不直接访问插件module下的PHP文件 |
| 普通浏览器没有按钮 | 正常，只在微信内注入；请发送链接到手机微信后打开 |
| 微信内完全没有专属内容 | 是否已安装、启用、绑定当前应用，是否开启网页功能，来源是否匹配，是否命中排除路径，是否为完整HTML页面 |
| 设置保存时提示AppID或来源不正确 | 对照对应章节检查长度、协议、末尾斜杠、端口、空格等；示例域名与凭据不能原样使用 |
| SDK初始化失败／按钮未出现 | 检查微信JS接口安全域名、校验文件、AppID与密钥对应关系、服务器公网出口IP白名单、服务器出站网络和微信实际权限 |
| 保存开启设置时提示API测试未通过 | 本次修改未保存；核对AppID与密钥是否属于同一账号、服务器出口IP白名单和网络，等待30秒后重试。原先已开启时保留原配置，如需停用请单独保存关闭状态 |
| 签名暂不可用 | 同上；修正后等待至少30秒失败冷却，再刷新页面，避免频繁重试 |
| 扫码能用但分享没变化 | 账号是否认证，两个分享接口是否加入列表，图片是否公开可访问，微信是否使用了旧分享缓存 |
| 分享都变成同一个标题 | 固定分享标题作用于所有页面；希望每页不同应留空并维护各页title |
| 定位按钮不显示或被拒绝 | getLocation是否允许、客户端是否支持、系统／微信定位权限是否允许；用户拒绝不会由插件强行开启 |
| 自定义HTML按钮没有反应 | ID与脚本是否一致，允许接口是否填写，脚本是否包含script标签，是否在用户点击时调用 |
| 卡券／支付开关开启仍不能用 | 检查账号类型、认证、实际专项权限、允许接口及业务服务器参数；开关不会创建业务能力 |
| 修改后看到旧页面 | 检查CDN／反向代理是否尊重private/no-store响应头，以及应用前端缓存 |

不要把密钥或完整凭证响应发给访客或写进页面。需要技术人员协助时，可提供去掉敏感参数的页面地址、账号类型、认证状态及错误现象。

## 凭证、缓存与访问范围

服务器通过固定的微信HTTPS接口获取stable_token和jsapi_ticket；提前120秒刷新，失败冷却30秒。缓存位于 `config/wechat_runtime/`，按AppID与密钥隔离，使用私有PHP文件、并发锁和原子写入，并自动创建空ignore文件排除框架打包。不要将运行目录另外作为静态文件发布。

签名动作只在已启用且绑定的前台应用内提供，仅为允许的当前来源签名，拒绝排除路径和跨站fetch请求。浏览器只接收AppID、随机串、时间戳、签名及接口列表，不接收密钥、token或ticket。UA只用于选择展示，不是用户身份认证。

绑定应用响应标记为private/no-store并增加Vary: User-Agent，微信内容在模板渲染后注入，避免普通浏览器与微信共用专属内容。严格CSP站点需允许官方SDK资源及插件脚本；不需要unsafe-eval。与其他系统共用公众号时，应统一考虑凭证和密钥维护。
