# MyStepFW 插件编写规范

整理日期：2026-10-18。目标运行环境：PHP 7.4。通用文件、命名、生命周期及辅助接口统一在此；六个现有插件的专属结构与维护说明另见 [现有插件](../docs/plugins/existing-plugins.md)。

## 1. 插件与应用的关系

| 项目 | 普通应用 | 插件 |
| --- | --- | --- |
| 源码归属 | app/应用名/ | plugin/插件名/ |
| 主类文件 | 应用名.class.php | class.php |
| 主类名与约束 | 应用名，继承 myStep | plugin_插件名，实现 interface_plugin |
| 对象角色 | 当前请求的框架控制器 $mystep | 生命周期及业务方法的提供者，通常采用静态方法 |
| index.php | 默认应用入口／页面分发 | 普通页面插件初始化，包含时 $this 为当前宿主控制器 |
| 生效声明 | 应用识别及路由配置 | 全局安装／活动状态、应用 plugin.php 绑定及具体入口条件 |
| 页面展示 | 应用主布局及功能模板 | 页面钩子、登记模块、独立路由或后台模块及对应模板 |

插件通过宿主控制器使用框架资源。不要为插件再创建一个 myStep 实例，也不要将插件专属类、函数、模板或第三方附属文件搬入网站根 lib。

## 2. 命名和目录对应

以短标识 `hello` 为例：

```text
插件目录：plugin/hello/
info.php：'idx' => 'hello'
主类文件：plugin/hello/class.php
主类声明：class plugin_hello implements interface_plugin
API 分组：plugin_hello
前置脚本安装目标：config/priority/plugin_hello.php
独立导出包：plugin_hello.plugin
```

目录、idx、类名后缀、安装辅助函数所用标识和应用绑定值保持一致，大小写也保持一致。显示名称 name 可以使用中文，不能代替 idx。

标识允许字母开头，后续使用字母、数字和下划线。前置脚本按 `plugin_`／`app_` 的固定前缀拆分，只剥离第一个前缀；插件标识中的下划线保持原样，目录、类名和注册记录仍须一致。

注册表长度存在历史差异：旧后台新建表时 idx 宽度为 10，Admin 新建表时为 40；已有表不会因为换后台就自动扩宽。需要兼容新旧后台及既有注册表时，新标识建议不超过 10 个 ASCII 字符，不能只按目录可创建的长度判断。

## 3. 通用目录骨架与必选范围

```text
plugin/hello/
├── info.php                    # 后台发现、展示及应用关联元信息
├── class.php                   # plugin_hello 与安装生命周期方法
├── index.php                   # 宿主插件初始化，登记钩子等
├── config.php                  # 可选：当前插件配置值
├── route.php                   # 可选：独立路由／API 声明
├── priority.php                # 可选：安装到框架前置目录的脚本源
├── config/                     # 可选：配置表单说明及字段结构
│   ├── construction.php
│   ├── default.php
│   ├── chs.php
│   └── en.php
├── language/                   # 可选：界面语言包
│   ├── default.php
│   ├── chs.php
│   └── en.php
├── module/                     # 可选：独立功能处理脚本
│   └── hello.php
├── template/                   # 可选：对应功能模板
│   └── hello.tpl
└── HelloHelper.class.php        # 可选：插件辅助类，明确引入
```

以后台可安装和普通页面可初始化为目标，提供 info.php、class.php 和 index.php。管理器的接口检查依赖前两个，框架 regPlugin 的普通初始化依赖 index.php。纯缓存插件可没有路由、模块和模板；无设置的插件不必制造空配置表单。asset、files 等资源目录可以按实际功能采用，但必须明确如何加载，不能假定所有插件资源都会被框架自动扫描。

## 4. 根脚本的职责与触发条件

| 文件 | 谁读取／调用 | 职责及约定 |
| --- | --- | --- |
| info.php | 后台扫描、插件登记等 | 返回 name、idx、ver、intro、copyright、description 等元信息；可提供 app 应用关联数组 |
| class.php | 管理器或插件明确 require_once | 声明 plugin_插件名，实现 check/install/uninstall，及插件业务方法；文件本身不是每次请求自动发现的入口 |
| index.php | myController::plugin | 在宿主控制器方法作用域执行，使用 $this 注册功能、钩子、语言和资源；不在这里执行安装过程 |
| config.php | 插件自身、配置管理页 | 返回当前插件参数数组；不会因文件存在就自动并入全局 $ms_setting |
| route.php | 路由重建及路由登记辅助函数 | 声明 $rule、$api，按需声明 $format；属于可编译的声明源，不保证每次请求执行 |
| priority.php | install 中 setPriority 显式复制；go 中前置扫描 | 在应用上下文和常规会话初始化之前执行；复制后 __DIR__ 指向 config/priority，引用源插件使用 PLUGIN 常量 |
| install.php | 仅具体插件自己的显式流程 | 不属于 interface_plugin 自动入口；manager 的同名脚本是生成独立安装包时采用的安装模板 |
| ignore | myPacker／manager 相关扫描 | 当前目录的排除规则；不是运行时路由或初始化屏蔽规则 |

### info.php 中的 app

app 是管理页的应用关联元信息，不是插件活动状态或 API 权限白名单。Admin 保存时保留声明的必需绑定；实际引用写入各应用 plugin.php。info 可能被列表扫描读取，避免业务写入和输出；需要控制器／语言上下文时明确依赖。

### class.php 的三个生命周期方法

| 方法 | 职责 | 返回及失败约定 |
| --- | --- | --- |
| check(&$result) | 检查扩展、目录权限和依赖，填充检查说明 | bool；后台查看也会调用，避免承担安装写入 |
| install() | 按需登记菜单、路由、优先脚本，建立本插件资源 | 管理器兼容无返回值，必需步骤失败应抛异常 |
| uninstall() | 对应移除登记和资源，按明确策略保留或删除数据 | 支持重复清理，不删除其他插件或应用的资源 |

安装／卸载调用的方法就是类方法，不是根据同名根脚本自动执行。各文件原子写入也不代表整个安装过程有事务回滚；插件应处理部分失败和重试。

## 5. 子目录与模块／模板对应

| 子目录 | 作用 | 与其他文件的对应 |
| --- | --- | --- |
| config/ | myConfig 配置编辑结构和字段说明 | config.php 保存值；construction.php 维护字段类型；chs/en/default 维护名称、说明及控件参数 |
| language/ | 插件界面语言 | 插件通过 setLanguagePack 明确加载，语言键使用 plugin_插件名_ 前缀以免冲突 |
| module/ | 每项功能的数据准备与动作处理 | 对应 template 下的功能模板；管理页面与注册模块的装配方式分别明确 |
| template/ | 插件功能展示 | myTemplate 赋值、循环和条件，不把业务操作塞进模板；通用插件模板辅助函数当前使用空 style |
| files/ 等资源目录 | 插件自带素材或第三方依赖 | 由插件显式选取并加入框架资源集合 |
| pack/、update/、rollback/ | 某些管理插件的包、暂存及回滚数据 | 由所属插件自己维护；目录有的在运行时创建，不是通用插件的必选目录 |

`config/default.php` 是默认配置表单说明，`language/default.php` 是界面语言文件，根 `config.php` 是当前值，三者不可互换。新旧管理页的语言选择和回退实现有所不同，需提供实际使用的语言版本，不假定任意缺失语言都会自动回退。

## 6. 两种页面装配及公共辅助函数

`showPluginPage($idx, $page='', $mode=null)` 先检查框架后台登录、管理员权限及插件启用状态，再创建子模板、包含可选的 module/页名.php，最后交给外层布局显示。页名为空使用插件标识，对应 template/页名.tpl 必须存在。模块在独立函数作用域中执行，可使用 `$tpl_sub`、`$tpl`、`$path_plugin`、`$page_app` 和历史配置别名；不能照搬 index.php 的 `$this` 上下文。模块已设置 `$content` 时直接采用，包括空串及字符串0，避免重复渲染。

第三参默认 `null`，按可信来源／显式展示标记自动选择后台；`true` 固定 myStep 原后台外层；`false` 沿用当前 `tpl_setting`，保留原接口含义。管理页始终关闭页面缓存，编译按插件及后台隔离。插件自身模块、模板、业务路由和权限约束保持独立，具体接入见第18节。

`setPluginTemplate($idx, $page, true)` 只创建框架原后台外层 main 和插件子模板；第三参 false 复用当前应用全局模板配置，由调用者继续装配。此低层函数不自动选择后台，也不代替鉴权。子模板关闭页面缓存，编译目录按插件及当前应用隔离，不修改全局模板设置。

| 辅助函数 | 用途与边界 |
| --- | --- |
| addPluginLink／removePluginLink | 更新 myStep/menu.json 的插件扩展菜单；只影响菜单，不建立路由或授权 |
| regPluginRoute／removePluginRoute | 同步插件路由源映射及编译规则；登记需要已有全局 router，无 route.php 时登记返回 false |
| setPriority／removePriority | 安装或移除 config/priority/plugin_标识.php；复制不等于当场执行 |
| setPluginApps | 统一同步应用绑定；合并强制应用，有序持锁，保留其他插件，数据不变时不重写 |
| setPluginOrder | 注册表内单次加锁保存0到99的运行顺序；无效输入不清空记录，同值顺序稳定 |
| buildPluginPackage | 隔离副本中生成plugin_标识.plugin；过滤在线配置和运行数据，返回file/name下载描述 |
| setPluginTemplate | 创建外层与内容模板，由调用者继续组装 |
| showPluginPage | 统一鉴权、模块与模板装配；默认按来源选择通用布局，不主动结束请求 |
| pluginPageHost／pluginPageApplication | 验证布局适配器／识别可信来源；只决定展示，不授予权限 |
| renderPluginPage | 校验框架管理员及启用状态，返回插件主体，供已有兼容入口使用 |
| pluginPageURL | 插件自身分页、筛选、表单及返回链接保留展示标记 |
| pluginAdminURL | 生成当前展示后台的设置、缓存等通用功能链接 |
| pluginQueryURL | 合并并编码查询参数，兼容查询字符串路由及片段；插入 HTML 时再转义 |
| pluginDirectory | 验证标识和插件目录，供受信路径构造使用 |
| changePluginMenu／changePluginRoute／savePluginFile | 低层受信更新，处理锁及原子发布；不代替管理入口鉴权 |

## 7. 运行时的几条独立链路

### 普通宿主页面插件

```text
建立应用上下文与常规认证
→ myStep::start 读取当前应用 plugin.php
→ 与 activePlugins 的活动标识核对
→ 按注册表 order 从大到小遍历活动插件，与应用绑定求交集并去重
→ regPlugin 登记有 index.php 的插件
→ 当前功能允许插件初始化时，myController::plugin 包含各 index.php
→ 登记模块／钩子／资源
→ start 钩子 → 模块和模板 → page 钩子及相应 end 收尾
```

同名 index 可在每个符合条件的新请求中执行，不应执行只能安装一次的动作。API、静态文件、跳转和功能忽略分支可能采用不同流程；end 不是所有请求都保证执行的 finally。

### 路由与 API

活动插件的 route.php 和显式 route_plugin 映射均可参与全局路由汇总，API 分组使用 plugin_插件名。对注册表已知或具有插件 info.php 的标识，显式映射也必须通过活动状态检查；停用后不再编译该插件的路由和 API。没有对应插件的外部显式路由源继续兼容。插件路由仍不受某个宿主应用 plugin.php 的范围限制，也不自动拥有后台权限；直接调用处理器时仍应检查活动状态和业务授权。不要把 route.php 的 include 当成每个请求的类加载器。

### 优先脚本

go 先读取全局配置，执行有效应用的前置脚本，再按注册表顺序执行活动插件的已安装前置脚本，早于路由、当前应用控制器和常规会话恢复。不能在这里假定 $this、当前应用 PATH、登录状态已准备好。停用不会删除复制文件，但框架跳过对应插件的前置脚本；卸载时仍须调用 removePriority 清理文件。前置脚本、来源目录为符号链接或缺少 info.php 时不执行。

## 8. 执行顺序、停用与缓存的明确约定

1. **order 越大越先初始化。** `activePlugins()` 按数值降序返回活动插件，相同 order 保持注册表原顺序。应用 `plugin.php` 只选择范围，重复绑定不重复初始化；插件前置脚本使用相同的插件顺序。应用前置脚本在插件前置脚本之前执行，不参与插件 order 排序。
2. **钩子阶段各有语义。** start/page 按登记顺序处理，end 按框架原有规则逆序收尾；order 不是“所有阶段都正序”。路由中的规则声明次序及不同路由组的匹配规则继续遵循路由器约定。
3. **停用不等于卸载。** 停用停止普通初始化、插件前置脚本及已知插件的路由/API 编译；保留菜单、源映射、脚本和业务数据，供重新启用。卸载清理自身登记与资源，不误删其他插件数据。业务处理器仍负责身份、权限、方法及 CSRF。
4. **请求内缓存不是永远不重读。** 插件注册表的内容指纹变化会刷新活动列表；路由指纹也包含注册表和生成策略版本。后台同一请求中的启停操作不会继续使用旧活动列表。
5. **注册表字段宽度仍有历史差异。** 旧后台 idx=10、Admin 初建 idx=40，存量表不自动迁移；order 等字段也以现有表头为准。不要用过长标识试探生产注册表。
6. **通用设置页与业务页独立。** config 生成表单并不自动保护插件自己的 module/template；也不意味着配置内容可以直接公开给 API。

## 9. 后续编写与维护时的对应关系

| 变更 | 同步核查 |
| --- | --- |
| 新增或重命名插件 | 目录、idx、plugin_类名、应用绑定、注册记录、路由/API、菜单、优先脚本及导出包名 |
| 新增设置项 | config.php、config/construction.php、各语言字段说明、运行读取和校验 |
| 新增页面 | 主类／路由或模块登记、module、对应 template、语言、资源、权限 |
| 调整独立 API | API 分组及回调、类加载、活动状态、参数、方法、权限、CSRF 及响应格式 |
| 增加优先脚本 | 安装复制、复制后的路径基准、执行前可用上下文、停用策略、卸载清理 |
| 调整缓存或资源 | 宿主对象引用、缓存键与失效、资源收集、应用绑定及跳过分支 |
| 准备发布包 | allow／ignore、运行数据排除、依赖、版本与文件基线，区分独立 .plugin 导出与 manager 的 .pack 更新资料 |

插件配置中的本地路径仍按网站根保存相对值，运行时通过 ROOT／myPath 解析；插件源码内部固定文件使用 __DIR__ 或 PLUGIN 定位，网页地址通过框架 URL 功能生成。源码和注释保持 PHP 7.4 兼容，公共调整同步核查应用及框架调用方。

## 10. 共享接口的原子更新与失败约定

`interface_plugin.class.php` 已补齐文件功能、方法目录、使用方式、生命周期接口及全部辅助函数的 PHPDoc，说明参数、返回结果、异常、全局依赖和页面模块作用域。

- 路由登记返回同步结果，没有源文件时不再写入无效路径；源映射旁路锁覆盖完整读改写，损坏映射在改动编译表前拒绝。内容未变时跳过重复写入。
- 路由/优先脚本清理仅要求合法插件标识，支持插件目录已删除和重复调用。优先脚本不再静默忽略复制结果，拒绝将意外同名目录递归删除。
- 菜单、路由源映射及优先脚本使用同目录临时文件完整写入后原子替换，保留已有目标文件的权限，拒绝符号链接目标；失败保留旧文件并清理临时文件。发布 PHP 文件后使 OPcache 失效。
- `setPluginTemplate(..., false)` 使用局部副本，修复子模板设置覆盖应用全局 `$tpl_setting` 的问题。子模板关闭页面缓存，避免应用外层/子模板共用缓存文件；缺少应用信息时编译目录使用 `myStep`。页名 `"0"` 不再误用插件默认页。
- 更新已有菜单项时同步修复父组链接，异常菜单组/子项保留原文件并明确报错。

保持已有辅助函数的调用参数兼容。`pluginDirectory()` 新增可选 `$required` 参数，默认仍严格验证目录；只有清理函数内部使用 `false`。框架和现有插件调用已复核，原调用无需调整。资源缺失以 `false` 返回，非法输入、损坏映射和保存失败抛出异常；生命周期接口仍兼容无返回值实现。多个文件或整个插件安装不具备整体事务回滚。

新增 `tests/plugins/plugin_interface.php` 的隔离场景（当前 29 项），覆盖实际路由/模板引擎、四进程路由登记、安装与重复清理、缺失资源、损坏配置、原子发布失败、模板全局变量及缓存、登录拦截及页面模块渲染。正式插件状态与业务数据没有变更。

## 11. 根目录的共享文件

interface_plugin.class.php 提供生命周期和公用辅助函数；plugin.db 保存插件注册状态；allow 供打包／文件扫描使用，不是加载或权限清单。具体目录和发布清单实例见 [现有插件](../docs/plugins/existing-plugins.md)。

## 12. 本轮审查形成的编码要求

### 配置与公开输出

- 保存阶段严格验证类型、应用标识、资源版本和文件边界；拒绝时保留旧配置。运行阶段可明确选择逐项容错，失效的一条资源选择不能使其他应用的有效选择全部失效。
- 公开 API 使用字段白名单。`construction.php` 把字段标成 password 只影响配置编辑，不会自动从 API 输出、日志或导出中删去该字段。sample 的公开接口只返回明确列出的非密码演示参数。
- 原始数据、HTML 文本、HTML 属性、URL 查询值和 JavaScript 数据分别编码。不要把 `" style="display:none` 等属性片段塞进 href；使用 `link`、`update_class` 等独立字段。
- 网页资源用 ROOT_WEB／模板 root_web，框架路由用 myStep::setURL，查询值用 pluginQueryURL；不要写固定域名、固定 `/console` 或根路径 `/vendor`。在配置或语言未异步加载完毕前，不直接调用依赖它们的前端路由函数；可由服务端输出最终 URL。

### 失败、文件和资源生命周期

- 必需的 regPluginRoute、setPriority、mkdir、打包和解包步骤都必须检查结果；失败抛异常或返回明确失败，不能仅根据下载大小判断安装成功。
- manager 的应用/插件更新统一调用 installPackage()，保留 myPacker 的完整预检、暂存及失败回滚；小于 1 KiB 的合法包也可安装，损坏包必须报告失败。管理员更新归档通过 manager/file 登录入口下载；公开更新源生成的差异归档通过 API 使用15分钟随机下载凭据，凭据只授权对应差异文件，服务端保存摘要。不要暴露整个 cache/tmp。整体配置迁移与整站热更新仍不是事务。
- 共享文件的读改写先持有旁路锁，再用 savePluginFile 原子发布。先检查原数据结构；损坏的封禁列表不能被当作空表覆盖。内容未变时跳过重复发布，并保持文件权限及 OPcache 一致。
- 临时文件按操作随机隔离，数据库连接保留宿主原引用；用局部 try/finally 与必要的 shutdown 清理应对返回、异常及 exit，不依赖普通 end 钩子统一清理。

### 容量、时间和后端边界

- PHP 的 `2M`、`1G` 是容量字符串，使用 myFile::getByte()，不能用读取文件大小的 getSize()。备份页取上传和 POST 的较小正上限；都不限制时隐藏 MAX_FILE_SIZE 使用 PHP_INT_MAX，不能写 0。
- Memcached timeout 配置为秒，原生连接选项为毫秒；TTL 超过 30 天转为绝对到期时间，转换后检查协议整数范围。原生 setOption/addServer 失败时拒绝产生看似可用的适配器。
- 命名空间和业务键采用结构化编码后哈希，避免分隔符可出现在数据中时发生跨命名空间碰撞。memoryCache 使用 ms:v3 键布局，原缓存自然过期；不在初始化时 flush 服务。

## 14. 类、方法、函数及回调的注释格式

插件自有代码采用与 lib 相同的中文功能说明及 PHPDoc 格式。保留原有作者和许可信息；注释类型用于阅读和 IDE 提示，不增加 PHP 7.4 原生类型限制。

1. 文件头按 **文件、功能说明、方法目录、回调目录（有闭包时）、使用说明** 排列。文件路径以网站根为基准；具名目录列出实际可见性、静态标记、参数及默认值，按源码顺序排列。没有具名声明的入口/模块写明这一点。
2. 类／接口单独说明职责、依赖、加载方式和使用边界；实现接口不等于已连接数据库、缓存服务可达或拥有后台权限。
3. 每个方法／函数以 **功能说明** 开头；显式参数逐项写 `@param 类型 名称 用途`，包含默认值和引用输入／输出语义。无参数入口明确写“无显式参数”。
4. `@return` 同时包含类型和含义；区分有效的 false/null/0、未命中、失败、输出响应及提前 exit。构造／无返回值入口使用 void；独立安装器的历史关闭句柄返回值须特别注明。
5. 关键异常使用 `@throws` 说明触发条件；已在内部捕获并转换为 false 的异常写清内部处理，不把它们全部写成必然向外抛出。
6. 使用全局控制器、配置、路由或共享清单时补充 `@global`；闭包单独说明用途、显式参数、返回值、通过 use 捕获的变量及绑定的宿主对象，不能把捕获变量误写为显式参数。
7. 文件、数据库、锁和缓存操作说明作用范围及释放方式；公开 API 写清字段边界，后台动作写清授权及 POST/CSRF 的承接位置，安装模板说明整文件执行的影响。

```php
/**
 * 功能说明：读取缓存值，并通过引用参数报告精确命中状态。
 *
 * @param string|int $key 业务缓存键
 * @param bool &$hit 引用输出：有效缓存记录为 true，否则为 false
 * @return mixed 缓存原值；未命中或后端失败为 false，应以 hit 判断

```

## 15. 生命周期一致性与独立 API

前置过滤、宿主初始化、独立 API 是三个不同入口：

| 入口 | 必要条件 | 与应用绑定的关系 |
| --- | --- | --- |
| 前置脚本 | 插件活动、已发布 config/priority 副本且源目录检查通过 | 全局执行，不要求当前应用绑定 |
| index.php 初始化 | 插件活动、当前应用绑定且未被本次入口的忽略规则跳过 | 按活动插件顺序与绑定求交集 |
| 声明的 API | 当前路由注册表包含活动插件的 API，目标处理器有效 | 不依赖当前宿主绑定；标准 class.php 按需加载，不额外执行 index.php |

将独立 API 所需的主类与方法放在 class.php，不依赖 index.php 的局部变量或只由宿主初始化创建的对象；需要的依赖在主类中显式声明。主类加载不代表通过身份和业务权限检查，API 方法仍须自行验证。停用插件不会因类文件存在而恢复其路由/API；不存在实体插件的显式外部 API 映射继续按原可调用处理器工作。

管理入口同步绑定时调用：

```php
// 安装/设置：管理员选择CMS，但插件声明必须关联myStep。
setPluginApps('hello', ['CMS'], ['myStep']);

// 卸载成功后清理所有应用绑定，不保留强制项。
setPluginApps('hello', []);

// 已安装插件的部分顺序修改；其他记录、启用状态及同值相对顺序保留。
setPluginOrder(['hello' => 8, 'another' => 3]);
```

这些写操作只由已验证管理员身份、POST与CSRF的管理流程执行，不放在 info.php、普通页面展示或公开 API 中。setPluginApps 返回实际改写的应用数；不创建无变化的空清单，按应用名顺序取得旁路锁，先校验全部清单再发布，并拒绝符号链接目标。它支持并发保留其他插件的修改，但文件I/O失败时不提供已经发布文件的自动回滚。

新旧后台都采用上述公共入口。运行顺序必须是0到99的整数或整数字符串，非法值／未知标识会抛异常并保留原注册表；不再先empty再insert。启停状态在同一注册表读改写锁中切换。卸载先执行插件卸载钩子，钩子成功后删除注册并清理绑定；已安装插件不能直接删除目录。

以上措施不把安装或卸载变为跨文件／数据库事务。插件卸载钩子自身已经删除的数据、外部服务副作用仍由插件负责，不能仅凭注册记录保留就认为发生了完整回滚。

新旧后台导出插件时共用`buildPluginPackage($idx)`：拒绝空标识，复制到独立临时目录，过滤在线config.php、约定的锁／数据库文件／日志和版本库信息。manager主类存在时只在副本中生成脱敏config_new.php，不依赖其已启用；不存在时不生成配置副本，也不会放行在线配置。返回`['file'=>临时路径,'name'=>'plugin_标识.plugin']`，交给框架文件输出接口；请求结束后自动清理暂存目录。原目录中的配置和旧导出副本不被覆盖或删除。


## 16. manager主服务器检查与在线／离线升级

`config/config.php`的`web.update`指定客户端使用的主服务器地址；`plugin/manager/config.php`的`update`控制本站是否对外提供更新服务，调试模式仍保留既有放行规则。两项用途不同，不通过域名自动判定“主服务器身份”。生产环境应关闭框架调试。更新地址使用HTTPS并验证证书及主机名，离线上传不依赖该地址有效或可达。

| 动作 | 入口 | 处理与结果 |
| --- | --- | --- |
| 查询主服务器版本 | `manager/check/version` → `api/plugin_manager/check/version?v=本地版本` | 主服务器按版本比较排序；客户端不提示同版或降级，连接／格式错误单独报告；同时刷新应用、插件版本表，包括空列表 |
| 下载离线更新 | `manager/download?m=0` | 下载并校验数据，只生成ZIP与受认证的下载链接，不执行迁移、不写回滚资料、不清缓存 |
| 在线自动更新 | `manager/download?m=1` | 获取数据后调用`applyUpdate`，预检目标、取得更新锁、备份旧内容，再发布文件／配置、执行迁移和清理缓存，最后提交版本与更新文件校验 |
| 离线更新 | `manager/upload`，上传ZIP | `applyUpdateArchive`验证ZIP及成员，兼容新清单包和旧版文件包，然后调用同一`applyUpdate`流程 |
| 应用／插件在线更新 | `manager/app/标识`、`manager/plugin/标识` | 从主服务器下载`.pack`，交给`installPackage`校验和发布；保留本机config.php，包中的config_new.php仅供参考 |

框架更新的传输仍为受限解压后的PHP数组序列化数据，保留`file/content/setting/code`四项；新增可选`kind`逐项声明`file`、`directory`或`delete`。未声明时按旧协议将空串解释为删除、单点解释为目录；显式声明为文件后可保留空文件、单点文件、字符串0及二进制内容。所有成员规范化后检查重复、父子冲突、私有路径及符号链接。

新离线ZIP的`_update.json`记录格式版本1、路径、操作类型、配置和迁移代码；普通文件保留相对路径，删除／目录操作无需伪造文件。上传时缺失文件、额外文件、混用新旧控制文件都会报错。旧ZIP的`_config.php`和`_code.php`继续兼容；迁移内容会执行PHP，只能使用可信发布来源。解包器自行生成的根锁文件不属于更新成员，不会复制到站点。

`createUpdateArchive($detail)`返回临时ZIP路径，需交给`artifactURL()`生成下载链接；`applyUpdateArchive($file)`不删除原ZIP，上传入口在finally中清理；`applyUpdate($detail)`失败抛异常，调用入口转换成JSON错误。新增方法的参数、返回及异常说明已写入主类PHPDoc。

更新锁阻止同时安装。恢复资料保存在`plugin/manager/rollback/时间_随机标识/`，不复用同一个版本目录；迁移或缓存失败时不提前提交新版本号。**这不是整站事务回滚**：已写入文件、配置以及迁移的数据库／外部副作用仍可能需要人工恢复，不应直接重试有非幂等副作用的迁移。归档生成失败也不能当作下载成功。

### 更新所需的PHP文件权限

在线更新与后台上传离线包都由Web PHP进程替换文件，因此权限条件相同。仅下载更新ZIP只需要暂存目录可写，不要求源码可写。PHP不能自行绕过操作系统权限；检查应以处理网站请求的PHP进程账号为准，终端PHP可写并不表示Web PHP可写。

| 相对路径／操作 | 权限要求 |
| --- | --- |
| 清单内待覆盖文件 | 旧内容可读以便备份，文件可写；所在目录可写且可搜索，缺失父目录可创建 |
| 清单内待删除文件／目录 | 旧内容可读；父目录允许删除，目录树内的目录可读、可写且可搜索；被删除文件本身不要求可写 |
| `cache/tmp/manager/` | 可创建暂存目录、更新锁与下载归档；已有锁可写 |
| `plugin/manager/rollback/` | 可创建唯一备份子目录，已存在时可访问、可写 |
| `config/version.php`、`plugin/manager/check_file.php` | 文件及父目录允许写入；校验清单写失败必须报告失败 |
| `config/config.php`及其`.lock`（本次含配置更新时） | 可读、可写；`config/`允许创建临时文件及以rename替换配置，已有锁可写 |
| `cache/script/`、`template/`、`language/`、`app/` | 缓存目录树可清理 |
| `cache/data/`、`v2/`及两位十六进制分片目录 | 可访问、可写；已有分片`.lock`可读、可写 |

更新器在发布任何源码之前检查上述已知位置，权限失败返回如`Update permission check failed: config/config.php.lock (write)`的相对路径错误；不会自动执行chmod/chown。可由站点所有者／服务器管理员通过所有权、专用用户组或ACL为实际PHP账号授权，同时确认新文件的权限继承。若PHP与源码所有者相同，通常目录755、文件644即可满足所有者写入；不同账号需要另外授予权限，不应统一改为777。采用临时更新权限时，完成后收回源码写权限，保留正常运行及设置保存所需的目录权限。

在线更新和离线上传的权限错误均包含操作及向Web PHP账号授权后重试的提示；manager页面在框架更新卡片中保留文字反馈，失败时不刷新页面或转到下载链接。实际发布文件及保存配置仍确认执行结果；预检后发生I/O错误时也标明更新成员或`config/config.php`，避免只有笼统失败信息。

预检只能检查当时可见的文件系统条件；只读挂载、ACL差异、并发修改、迁移脚本及外部缓存服务仍以实际操作结果为准。更新器继续逐项确认执行结果，失败不提前提交版本。手工部署需另行处理配置合并、删除项及迁移，不能把新离线ZIP简单解压视为完整升级。

主服务器下载缓存同时包含发布清单及成员内容指纹；同版本修订内容后不会复用旧缓存。新日志表使用19字节日期列；旧10字节列保留并按日期写入，不需要清空已有升级记录。

回归入口：`python3 tests/plugins/manager_upgrade_http.py`。夹具使用临时主服务器和客户端、真实PHP 7.4、严格验证的本地HTTPS以及真实multipart上传；37组场景、55次客户端HTTP请求覆盖框架在线／离线更新、应用／插件更新和文件权限边界。权限测试以普通用户运行，在隔离副本中临时调整模式并恢复；覆盖源码、备份、配置锁、清单、缓存分片锁、递归删除等位置，断言权限失败前未替换首个文件，且更新器不放宽权限。管理身份由夹具模拟，只验证插件是否调用授权检查；完整登录和CSRF边界由安全／后台回归另行覆盖。不会升级正式站点或重新生成正式发布清单。

## 17. manager整站打包、独立安装与安装后升级

`/pack/`是受管理员登录、POST和CSRF保护的安装包生成入口，与`manager/download?m=0`的离线更新包用途不同。打包开关仍由manager配置控制；`pack=false`且框架非调试模式时拒绝操作。成功返回通过`manager/file`认证下载的地址，支持子目录及框架路由模式，不公开整个临时目录。

`createSystemArchive()`在权限为0700的独立暂存目录导出文件，保留框架的缓存／会话驱动、应用和插件的功能配置、construction定义及默认菜单。在线根config.php、域名绑定、插件注册、日志、数据库、根files上传目录和运行缓存不导出；组件配置使用已有默认值，或按密码声明及常用敏感键脱敏。应用仍须在结构中声明密码字段，源码内任意硬编码凭据不属于配置脱敏范围。整个过程不改在线配置，也不生成／删除在线config_new.php。

各目录原有allow／ignore继续生效；`app/allow`已补入Admin，其他既有项目不变。非根目录的公共asset/files目录保留，不能仅因目录名为files就当作上传数据删除。发布不含数据库备份；组件数据、站点配置和插件启用状态需要新站自行设置。

系统包包含`mystep_v版本/index.php`独立安装页、`mystep.pack`框架载荷、readme和`install-assets/`下的本机jQuery／Bootstrap。安装页面不依赖CDN。内容摘要覆盖导出文件和安装资源，同版本源码变化会生成新包；缓存ZIP有独立完整性摘要，损坏后重建。打包过程有独占锁，源文件／大小预算／ZIP生成失败会报错，不返回虚构下载地址；压缩载荷限64MiB、展开限256MiB，与独立安装器限制一致。

独立安装需在全新目录执行：解包生成的ZIP，打开其中index.php，安装页携带会话令牌POST释放文件；成功后清理安装器并进入框架初始化。安装脚本固定使用自身所在目录，避免工作目录影响目标。首次初始化在根配置尚不存在时合并完整默认配置，再应用提交值，避免空密码等字段被跳过后缺失；初始化资源地址使用站点根前缀。独立安装器不在已有config/config.php的网站上运行，失败时页面停止轮询并显示重试提示。

安装页先检查安装根目录、日志、源包读取及安装器副本的权限，显示检查结果；失败返回HTTP 403并禁用安装按钮。点击安装后重新检查配置初始化目标及全部归档成员，文件/目录类型及父子关系也在释放首个文件前检查。权限错误显示相对于安装目录的路径、操作和授权建议，不再统一误报为“安装包有误”。`InstallAccess()`不修改既有权限，`rewritable()`保留布尔查询入口。

`MakeDir()`只将新建目录设为0755；解包临时文件先设为0600，完整写入后以0644原子发布，保留PHP所有者的后续维护权限。已有目录权限不变；已有文件由新文件原子替换时使用新文件的0644模式。新建日志、配置辅助文件及安装器副本也保留所有者写权限，不依赖服务器当前umask。日志与配置的`WriteFile()`改为加锁后完整写入并返回字节数，失败抛异常，不再把已关闭的句柄当作成功标志。

`unpacker::DoIt($separator='|', $remove=true)`增加可选的延迟清理参数；安装页面传false，等配置初始化全部成功才删除源包。失败保留源包以便修复权限后重试；已发布文件不保证整体回滚。进度日志仅用于显示，页面收到安装POST明确的`done!`后才显示完成并进入清理；配置写失败、网络失败或迟到的进度响应都不能触发成功跳转。清理安装器及恢复Web服务器配置也会预检权限并确认操作结果。

**安装ZIP不能上传到manager/upload当作离线更新**，入口会明确拒绝。已有站点更新应使用`manager/download`生成的更新包；配置和迁移流程仍按第16节执行，整站更新并无跨文件、配置和数据库的完整事务回滚。

## 18. 插件后台通用布局适配

所有通过 `showPluginPage()` 展示的插件管理页共用来源识别、主体渲染与外层布局机制。已接入 myStep 和 Admin；manager、myBackup、frontend、badReq、sample 无需逐个增加 Admin 路由或模块。插件内容仍从自己的 `module/` 和 `template/` 读取，后台只提供一次公共布局适配。

| 进入方式 | 展示规则 |
| --- | --- |
| 从可信 `/Admin/` 功能页打开 `/frontend/` 等插件页 | 保持插件原路由，首次 GET 补 `_plugin_app=Admin`，使用Admin导航和模板 |
| 刷新或提交已有标记的插件页 | 延续相同布局；POST直接处理，保留原会话、动作参数与CSRF检查 |
| 空Referer且无显式标记、原后台、非法／外部来源 | 使用myStep；不把布局选择写入会话 |
| 其他已提供通用适配器的应用 | 使用该应用适配器；没有适配器时回退myStep |

来源识别兼容重写、PATH_INFO、query_string、子目录和已登记域名绑定；配置的原后台 path_admin 始终归入 myStep。只收到来源域名且没有应用绑定时，无法推断具体后台，按myStep处理。Referer与标记只选择外层，不能替代登录、管理员权限或插件活动状态检查。

### 插件作者的接入

管理路由继续调用：

```php
showPluginPage('demo'); // 自动识别外层；读取module/demo.php和template/demo.tpl
```

公共内容模板预先获得 `root_web`、`path_admin`、`plugin_setting_url`、`plugin_page_url`。`plugin_page_url` 使用当前实际URL，兼容路由别名；HTML属性中使用 `<!--plugin_page_url|html-->` 等转义形式。未指定action的表单沿用当前URL及布局；自建URL使用公共函数：

```php
$listURL = pluginPageURL(myStep::setURL('demo/'), ['page'=>2, 'keyword'=>'例子']);
$settingsURL = pluginAdminURL('function/plugin/setting/', ['idx'=>'demo']);
$cacheURL = pluginAdminURL('function/cache/');
```

链接插入HTML前转义，插入JavaScript则用 `json_encode` 配合 `JSON_HEX_TAG|JSON_HEX_AMP|JSON_HEX_APOS|JSON_HEX_QUOT`。JavaScript修改现有URL可使用框架 `queryURL` 保留布局参数。插件自己的分页、筛选、跳页、重定向均需遵循此规则；badReq已同步处理，myBackup的数据库切换继续使用原URL合并参数。

`_plugin_app` 为保留参数；公共入口在执行模块前从POST和REQUEST移除，GET中保留供地址续用。插件业务代码不要以此参数作为业务数据或权限依据。第三参显式 `true/false` 的旧调用保持原有固定／当前模板行为；直接使用低层 `setPluginTemplate` 的独立前台展示不自动套后台。

### 后台应用只需提供一个适配器

在应用根目录提供可选 `plugin_layout.php`，返回可调用对象。公共入口只读取合法应用目录下的固定文件，不接受请求指定任意文件路径：

```php
<?php
require_once __DIR__.'/Hello.class.php';
return ['Hello', 'pluginLayout'];
```

应用核心类的 `public static pluginLayout($body, array $context)` 接收已经渲染的可信插件HTML，以及 `plugin/page/app/title` 上下文，返回 `myTemplate`，由原业务控制器统一输出。适配器在自己的应用目录内准备导航、对应功能模板和本地CSS/JS，遵循应用的模板path/style/default回退；不要重复执行 `myStep::init/start`、启动会话或替换业务配置、数据库、路由及控制器。临时模板／应用上下文必须在异常时也恢复。

Admin实现位于 `app/Admin/plugin_layout.php` 和 `Admin::pluginLayout()`，通用功能模板为 `template/default/plugin.tpl`。自定义风格可提供 `main.tpl` 和 `plugin.tpl`，未提供时遵循原框架default回退；通用内容样式限定在 `.adm-plugin-page`。CSS/JS缓存按插件及布局配置隔离，页面和内容均不缓存。CMS等其他后台若要采用自身布局，需要按同一协议提供一次适配器。

已有 `/Admin/manager/`、`plugin_manager::pageApplication()` 和 `pageContent()` 保留为兼容入口，内部委托公共逻辑；新插件不复制manager的专用模块。页面鉴权、GET写入拒绝及POST CSRF验证仍由原框架和插件入口负责，展示适配不绕过这些流程。
