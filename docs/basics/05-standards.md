# 开发规范

本章说明在框架中编写应用和插件时的代码归属、加载方式、数据处理及注释要求。标识、变量、函数和方法的具体写法见[命名规范](09-naming.md)，各阶段适合放置的代码见[执行流程](../backend/runtime/execution.md)。

## 文件归属

- 普通应用放在`app/应用名/`，核心类与应用同名，并继承`myStep`。
- 页面功能代码放在`module/`，展示放在对应的`template/`；应用复用的函数和辅助声明集中于已有`lib.php`。
- 插件放在`plugin/标识/`，主类为`plugin_标识 implements interface_plugin`；安装、请求初始化及优先脚本分别承担自己的阶段职责。
- 应用或插件专属功能留在自己的目录，不放入根`lib/`；根`lib/`提供通用框架能力。
- JavaScript、CSS和图片保存在所属应用或插件的资源目录，通过框架登记使用。

目录、脚本职责及模块／模板对应关系见[应用规范](../../app/README.md)和[插件规范](../../plugin/README.md)。

## 加载与执行

根`index.php`统一调用`myStep::init()`。框架已启动的应用模块直接使用当前`$mystep`、`$ms_setting`、`$db`等对象，不重复初始化框架或会话。

`lib.php`主要声明复用的函数和类，`route.php`声明路由及API，不在声明文件顶层执行安装、批量写入或输出页面。每次请求的逻辑放到明确会执行的入口、模块、处理器或钩子。

`preload()`早于默认服务初始化及身份恢复。需要当前会话和登录身份的逻辑放在`start`钩子、业务处理器或模块中，并继续做业务授权。覆写`start()`、`end()`等方法时保留父类对应流程。

## 路径与配置

配置保存网站根相对路径，程序通过`ROOT`解析磁盘位置；网页地址通过`ROOT_WEB`及`myStep::setURL()`生成。磁盘路径、路由路径和浏览器URL分别处理，避免写死部署域名或服务器绝对路径。

配置字段同时提供默认值、各语言结构和读取时的默认处理。应用通过自己的`info.php`声明标识、名称和组件版本；框架的系统版本不作为应用标识使用。

## 输入、权限与输出

1. 请求值先检查类型、长度、范围及数组结构；请求中的文件名和回调名不能直接决定可执行目标。
2. 数据库值使用参数绑定，表名、字段和排序通过受信映射选择。
3. 每个受保护页面及API都校验身份、业务权限及记录归属；隐藏按钮不构成权限控制。
4. 状态修改使用合适的请求方法及框架CSRF校验。浏览器checkForm通过后，服务器继续验证输入。
5. HTML文本、HTML属性、URL、JSON和JavaScript分别采用对应编码方式。
6. 原始API、文件和跳转响应不混入调试文字或页面HTML。仅需页面片段时使用`render()`，完整输出交给明确的页面出口。

## 方法与注释

运行环境以PHP8.5.12及以上8.x为基线。参数类型、返回类型及可见性与继承关系一致；覆写方法须核对父类／接口签名。

每个文件说明用途、加载条件及主要声明；方法和函数注明功能、参数、默认值、返回值及必要异常。修改公共方法时同步检查框架、应用、插件、模板及脚本中的调用点。

```php
/**
 * 功能说明：判断文章是否属于当前站点。
 * @param array $article 已读取的文章记录，含web_id字段
 * @param int $web_id 当前站点编号
 * @return bool 归属相同为true，否则为false
 */
function belongsToSite(array $article, int $web_id): bool
{
    return isset($article['web_id']) && (int)$article['web_id'] === $web_id;
}
```

示例只判断记录归属；实际读写还需校验当前用户是否有权操作该站点和记录。

## 调试与验证

新功能先在独占临时目录、测试账号或隔离数据库中验证。按实际使用场景检查正常结果、未登录、无权限、输入不合法、资源缺失及并发保存等分支。记录具体失败原因后修正，不以清空日志代替处理问题。

排查加载顺序时先确认请求属于默认页面、显式规则、API还是文件分支，再检查对应阶段；不能假设所有请求都会执行`global.php`或`end`钩子。
