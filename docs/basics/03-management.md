## 3. 功能设置：按职责查找管理入口

新后台通常为 `/Admin/`；原后台通常为 `/console/`，原路径可配置。下表使用功能名称定位，避免把固定域名或后台路径写进通用代码。

| 功能 | 管理内容 | 需要理解的边界 |
| --- | --- | --- |
| 参数设置 | 全局或应用配置，按 `myConfig` 结构生成表单 | 密码、列表、开关与普通文本有不同转换规则 |
| 类加载设置 | 搜索目录、扩展名、特别指定的类文件 | 指定目录相对网站根；索引映射相对该搜索目录 |
| 域名绑定 | 将主机名关联应用或虚拟入口 | 与实际 DNS、证书和站点配置配套 |
| 应用管理 | 应用信息、绑定插件、应用设置及语言等 | 目录名、应用标识和同名核心类保持一致 |
| 插件管理 | 发现、安装、启停、顺序、应用绑定及配置 | 安装、活动状态和页面初始化是不同阶段 |
| 缓存管理 | 按后台明确范围清理生成缓存 | 与驱动 `clean()` 的过期回收含义区分 |
| API 管理 | 每个接口的启用、允许方法、跨域开关、仅限后台 | 只管理已登记接口，不开放任意回调 |
| 错误日志／框架指南 | 读取与排查、按分类阅读说明 | 日志、配置和源码不应通过普通公开地址下载 |

API 全局参数位于“参数设置”的主框架 API 分组，只有启用、默认格式、正文上限、专属域名四项；逐接口设置在“API 管理”对应行下展开，以 AJAX 应用。调用地址为不附加格式尾段的纯文本。详见[API 调用与后台管理](../backend/runtime/execution.md)。


## 操作步骤与注意事项

相关配置以当前框架设置和对应应用覆盖为准。普通应用使用同名myStep子类；类与模块放在自己的目录。文件系统路径和浏览器URL分别生成，不复用本机绝对目录作为可发布设置。

## 验证与进一步阅读

示例中的文件、数据库和变量按本篇前提准备；涉及写入时使用独占临时目录或隔离库，按明确返回值和异常验证。源码中的public/protected/private、引用参数和可选接口是实际契约，不能只按方法名猜测返回或能力。
