# 框架概要与执行主线

## 本篇目标与调用场景

从框架入口与目录职责建立正确的开发上下文，明确功能由哪个阶段、文件和对象承担。

## 4. 框架概要：读懂请求主线

[执行流程](../backend/runtime/execution.md)逐阶段说明文件调用、变量可用时刻及提前出口；应用文件的实际记录示例见[执行顺序](../development/app/app-07.md)。

```text
Web 服务 → index.php → myStep::init()
  → 类加载、已解析输入预算、初始异常处理
  → myStep::go()：全局设置、前置脚本、域名、路由
  → 命中显式规则，或选择默认承接应用
  → setPara()：当前应用、核心类、配置及上下文
  → preload/start：按条件准备会话、CSRF、认证、插件和资源
  → 处理器／页面模块／注册 API
  → 页面渲染与 end，或文件／API／跳转等专门结束路径
```

这是一条阅读主线，不是所有请求都完整经过每一项。公共资源、合法 API 预检、缓存命中和拒绝请求可能提前返回；`global.php`、插件 `index.php`、`show()`、`end()` 不保证在每种分支执行。完整顺序、变量生效时间和退出点见[详细执行流程](../backend/runtime/execution.md)。

`mySecurity` 在不同阶段处理已解析输入预算、会话 CSRF 和输出中的令牌装配；`myAuth` 负责密码及记住登录凭据等辅助能力。二者都不能替代业务中的用户身份、数据归属和操作权限判断。

## 操作步骤与注意事项

相关配置以当前框架设置和对应应用覆盖为准。普通应用使用同名myStep子类；类与模块放在自己的目录。文件系统路径和浏览器URL分别生成，不复用本机绝对目录作为可发布设置。

## 验证与进一步阅读

示例中的文件、数据库和变量按本篇前提准备；涉及写入时使用独占临时目录或隔离库，按明确返回值和异常验证。源码中的public/protected/private、引用参数和可选接口是实际契约，不能只按方法名猜测返回或能力。
