## 本篇目标与调用场景

从框架入口与目录职责建立正确的开发上下文，明确功能由哪个阶段、文件和对象承担。

## 2. 基础配置：先保证入口和目录正确

将 Web 服务的站点目录指向网站根目录，动态请求转入 `index.php`，PHP 类库、配置、数据库文件、日志等私有资源不能作为普通静态文件公开。仓库提供的服务器配置是部署参考，需要合并到实际虚拟主机后验证。

首次安装与已有站点的区别是全局 `config/config.php` 是否存在：缺失时进入安装初始化，存在时按正常流程运行。不要为重新安装而直接删除已有站点配置；先备份配置、数据库和业务文件。

| 设置位置 | 作用 |
| --- | --- |
| `config/config_default.php` | 框架默认项目及安装基础，不作为站点口令记录 |
| `config/config.php` | 当前站点全局配置 |
| `config/construction/` | 全局配置表单的字段名称、说明、类型及语言 |
| `app/应用名/config.php` | 当前应用覆盖项 |
| `app/应用名/config_入口名.php` | 匹配相应入口时使用的配置覆盖，须符合当前分发条件 |
| `config/domain.php` | 可选域名绑定；不等同于 DNS、证书或 Web 虚拟主机 |
| `config/class.php`、`config/route.php` | 类加载与路由相关索引／登记数据，由相应机制管理 |

持久化的站内文件路径以网站根为基准，例如 `app/Hello/template/`、`cache/session/`。运行时由 `ROOT`、`myPath` 等组合为绝对路径。浏览器地址通过 `ROOT_WEB` 和 URL 生成器处理；磁盘路径与网址不能混用。完整规则见[路径与类加载](01-guide-basics.md)。

安装及更新需要 PHP 进程对实际目标具有相应权限。创建文件取决于父目录权限，替换、删除还受目录所有者、ACL、只读挂载等条件影响；不能仅根据一个 `is_writable()` 推断全部后续操作一定成功。当前安装／更新流程会检查目标及报告失败，具体操作仍须核对结果。


## 操作步骤与注意事项

相关配置以当前框架设置和对应应用覆盖为准。普通应用使用同名myStep子类；类与模块放在自己的目录。文件系统路径和浏览器URL分别生成，不复用本机绝对目录作为可发布设置。

## PHP 最低版本、许可证与抓取配置

主入口 `index.php`、manager 独立安装模板和 Composer 的最低要求统一为 **PHP 7.4.0**。当前缓存函数的对象身份依赖 `WeakReference`（PHP 7.4 引入），配置与模板 JSON 解析也使用较新的 PHP 7 功能，因此旧的 PHP 7.0 提示不再正确。OpenSSL、Sodium、数据库及图片扩展按所选功能启用；最低版本检测并不代替扩展检查。本轮以 PHP 7.4 验证，不据此声明 PHP 8 的全部兼容性。

框架的 `LICENSE.txt` 是 Apache License 2.0 官方标准全文，本次与 [Apache 官方文本](https://www.apache.org/licenses/LICENSE-2.0.txt) 逐字节核对一致；标题中的 January 2004 是许可证版本日期，不需要随框架版本或年份修改。各第三方组件保留自己的许可证。

根目录 `robots.txt` 允许抓取公开页面和渲染资源，排除后台、API、配置、公共类库、运行数据及本机文档源码；`cache/script/` 中的公共脚本和样式继续允许。后台/API 排除覆盖重写、PATH_INFO 和查询字符串三种入口。自定义后台路径或部署在子目录时应按真实 URL 增补规则；独立 API 域名也须提供对应主机的抓取策略。

框架没有可对所有应用通用的站点地图内容，因此默认不声明一个未经配置的 Sitemap 地址。应用启用真实站点地图后，在 robots.txt 写入包含协议、域名的完整地址。robots.txt 是搜索引擎抓取约定，访问权限仍由服务器、路由和后台认证控制。

GitHub 当前代码与整站安装包不包含根目录 `test/`、`tests/`、`maintenance/`、`AGENTS.md` 及 `docs/backup/`；这些资料仅在开发者本机保留。开发文档中出现的测试命令是本机验证入口，下载运行版无需这些目录。
