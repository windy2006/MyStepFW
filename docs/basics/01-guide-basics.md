# 整体介绍与框架组成

## 本篇目标与调用场景

从框架入口与目录职责建立正确的开发上下文，明确功能由哪个阶段、文件和对象承担。

## 1. 整体介绍：框架负责什么

迈思 PHP 框架系统（MyStepFW）以网站根目录的 `index.php` 为统一动态入口，通过 `myStep` 组织路由、配置、应用、会话、插件、模板及响应。普通页面、API、静态文件、下载和跳转分别具有自己的完成路径。

| 层次 | 主要代码 | 开发者的工作 |
| --- | --- | --- |
| 公共底座 | `lib/`、`lib/function.php` | 复用文件、请求、字符串、数据库、缓存等公共能力 |
| 控制与路由 | `myStep`、`myController`、`myRouter` | 声明入口、选择当前应用、准备上下文 |
| 应用 | `app/应用名/` | 实现业务模块及对应模板，不复制框架启动流程 |
| 插件 | `plugin/插件名/` | 提供可安装、启停、绑定应用的独立扩展 |
| 展示 | `myTemplate`、`static/`、应用 `asset/` | 组合页面、加载本地资源、完成前端交互 |
| 运行数据 | `config/`、`cache/`、`files/` | 保存设置、索引、缓存、会话及上传数据 |

框架通过类索引、路由编译、模板编译、数据及页面缓存、资源整合和流式文件输出减少重复工作。是否启用页面缓存、数据库自动连接和插件，取决于当前应用及请求。缓存命中率、查询数量和响应时间应在自己的业务负载中测量，不能仅凭“已启用缓存”判断效率。

`app/myStep` 是框架自带管理应用，`app/Admin` 是同一机制下的新管理应用；CMS 等具体业务应用的配置和表结构不属于通用框架的必选项。具体应用与通用框架规则分别维护，通用应用组织见[应用实战](../development/app/README.md)。

## 操作步骤与注意事项

相关配置以当前框架设置和对应应用覆盖为准。普通应用使用同名myStep子类；类与模块放在自己的目录。文件系统路径和浏览器URL分别生成，不复用本机绝对目录作为可发布设置。

## 验证与进一步阅读

示例中的文件、数据库和变量按本篇前提准备；涉及写入时使用独占临时目录或隔离库，按明确返回值和异常验证。源码中的public/protected/private、引用参数和可选接口是实际契约，不能只按方法名猜测返回或能力。
