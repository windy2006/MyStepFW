# 路由声明、配置管理与对象代理

整理日期：2026-10-18。目标运行环境：PHP 7.4。数据库和缓存使用各自主题文档；同类旧概要不再重复维护。

## 路由 myRouter

### 已修复的行为

- 普通规则仍按原来的正则语义注册，但完整匹配边界覆盖整个顶层分支，避免 `/a|/b` 意外匹配 `/a-extra`。
- 编译时选择不与规则冲突的分隔符，规则中的 `#` 等字符不再直接破坏正则。
- 自定义格式预先验证，不接受会破坏捕获参数位置的命名组及反向引用。原来普通内部捕获组继续转为非捕获组，外层只保留一个参数。
- 原始正则规则中的命名捕获只按数字捕获顺序传递一次，不把同一个参数重复传给处理器。
- PCRE 执行失败会抛异常，不再把回溯资源不足当成“没有规则匹配”而继续走应用回退。
- 同一对象多次检查不同 URL 时保留绑定前缀，并同步更新实例和全局应用信息。
- 重解析查询后按 PHP 的 request_order/variables_order 重建 REQUEST，POST/Cookie 的优先级遵循配置，旧 GET 参数不会残留。
- 持久路由只接受可导出的普通数据和命名回调；不再把看起来像 `function(){...}` 的字符串反转义成可执行 PHP。闭包及对象回调仍可在内存注册。

### 字面路径接口

```php
$router->literal('/article/[int].json', 'articleHandler', 'MyApp');
```

仅已定义的命名占位符使用正则，`.` 等字符按字面匹配；未知占位符报错。旧 `rule()` 保持正则语义，已有规则无需全部改写。

路由声明及正则仍是受信开发配置，不是面向不可信用户的正则沙箱。路由优先级保持“直接规则先于绑定前缀规则，同一轮按声明顺序首个匹配”。

## 配置 myConfig

### 类型、合并和读取

PHP/JSON 加载和导出保留实际类型，包括 null、布尔值、数字、数字文本和列表，不再把字符串 `false` 猜成布尔值，也不把 null 读成空对象。数组与对象转换使用新容器，不修改传入对象；链式访问仍以对象形式提供，导出为数组时还原嵌套列表。

INI 沿用文本配置约定，对 true/false 做兼容恢复；复杂嵌套及严格类型往返优先使用 PHP/JSON。公开的 recover() 兼容辅助方法保留，类型保真的 PHP/JSON 转换不再调用它猜类型。

合并支持标量节点被配置分组替换，保留 null，并避免将外部对象引用直接挂入配置。克隆实例会复制嵌套配置。

```php
$value = $config->value('db.port', 3306); // 路径不存在时不创建节点
isset($config->section);
unset($config->temporary);
```

原来的 `$config->newSection->item = ...` 仍可自动创建分组；需要无副作用读取时使用 value()。

### 设置表单和结构

- 缺少 construction 文件时仍可更新普通设置，结构信息在实例中复用。
- 配置结构从当前定义生成，不再无条件沿用陈旧的派生结构；内容相同不重复写入。
- set() 保留表单列表转换为 CSV 的历史约定，按已有明确类型处理数值和开关，文本字段保留前导零及字面 true/false。
- 空密码不覆盖原值，字符串 `0` 可作为新密码；密码变换回调仍遵循结构定义。
- 部分分组提交不会顺带清空其他分组中未提交的开关和复选框。
- 配置控件转义实际值，保留反斜杠，并依据原始布尔值显示开关；选项比较在 HTML 转义之前进行。

### 原子保存和并发冲突

保存先完整编码，再锁定同目录锁文件、写入同目录临时文件并原子替换；失败时保留原文件，并保留已有文件权限。新文件默认 0600。保存后使对应 OPcache 失效；不再因普通值更新反复删除未变化的配置结构。

保存原文件时比较加载时的内容摘要，检测其他请求已经保存的修改，冲突抛 RuntimeException，提示重新加载。需要明确覆盖时可使用第三个参数：

```php
$config->save();                  // 默认拒绝覆盖并发修改
$config->save('php', '', true);   // 调用方明确选择覆盖
```

保存到不同文件的导出不套用原文件的版本检查。JSON 编码失败、根节点不是数组/对象、无效格式和读取期间持续变动都会明确报错，避免写入空配置或陷入格式回退循环。JSON 文本要求有效 UTF-8，不猜测原编码。

## 对象代理 myProxy

- 被代理类有构造函数时由构造函数负责初始化，只调用一次；没有构造函数时才使用可调用的 init()。
- 支持直接代理已经初始化的对象；失败的初始化不会替换原有可用对象。
- 支持虚拟属性的 get/set/isset/unset，以及值为 null 的公开属性，避免误回退或访问受保护成员。
- 显式注册的方法别名优先于目标的魔术分发，拒绝循环别名；保留普通方法及旧别名行为。
- 释放对象时不再逐个 unset 静态属性，避免析构阶段触发属性转发或访问已经被移除的目标。
- 数据库和缓存的目录自动加载器每类只登记一次，避免反复创建实例时持续增加重复回调。

旧 `__get()` 的非引用签名保留，以兼容 myReflection 和其他既有子类。需要修改公开数组属性时显式使用引用入口：

```php
$items =& $proxy->propertyReference('items');
$items[] = 'new item';
```

此入口仅允许公开属性或明确支持引用返回的虚拟 getter。普通虚拟 getter 的值依然按目标类自己的语义返回。代理不提供权限隔离，目标类仍须来自受信代码。
