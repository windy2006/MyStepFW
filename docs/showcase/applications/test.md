# test：执行流程观察应用

## 定位和适用场景

用于观察框架上下文和流程，使用站点本身的配置。与开发者运行的tests/隔离回归不同。

## 当前目录及主要文件

源码位于`app/test/`。以下为当前源码层级，不表示所有文件都会自动执行：

```text
app/test/
├── asset/
├── config.php
├── config/
├── global.php
├── index.php
├── info.php
├── lib.php
├── module/
├── plugin.php
├── route.php
├── template/
├── test.class.php
```

## 入口与执行过程

test.class.php及index.php由框架应用分发加载；访问时按实际站点上下文运行。

## 配置、模板和资源

设置、语言、模板与asset/files等资源保持在本项目内；共用框架服务通过当前应用上下文调用。配置值与后台字段结构分别维护，表单客户端用checkForm，服务端仍校验权限、方法和CSRF。

## 使用步骤

1. 在测试站核对本项目目录、元信息和所需扩展。
2. 按已登记路由访问应用入口，并选择对应功能。
3. 先执行只读展示，再在独占测试资源中验证保存或管理动作。
4. 检查模板风格、窄屏、资源地址、会话与失败反馈；不在正式数据上试验安装或恢复。

## 边界与维护

模块与模板按功能对应。应用实例和数据作用域独立；此项目的专属目录、表结构或页面清单不自动成为其他应用的通用要求。
