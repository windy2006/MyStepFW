# 现有插件结构与维护

整理日期：2026-10-18。目标运行环境：PHP 7.4。本轮逐项审查六个插件的主类、初始化、路由、配置、模块、模板和共享调用链；在既有维护记录基础上补充 2026-10-18 的修正。

## 实际 plugin 根目录

```text
plugin/
├── interface_plugin.class.php  # 生命周期接口及公用插件辅助函数
├── plugin.db                   # simpleDB 插件注册表，管理动作维护
├── allow                       # 打包／文件校验扫描的允许清单
├── sample/                     # 钩子、模块、标签、配置及编辑器扩展示例
├── frontend/                   # 按应用选择前端组件版本
├── badReq/                     # 请求过滤、封禁及日志管理
├── manager/                    # 更新、校验、打包及发布相关管理
├── myBackup/                   # 数据库备份及表维护
└── memcached/                  # 替换当前应用使用的数据缓存驱动
```

`.DS_Store` 是系统元数据；`.lock` 是运行时并发辅助文件，均不属于新插件骨架。目录存在不等于已安装，已安装不等于启用，也不等于在每个应用中初始化。

### 公用文件的作用

- `interface_plugin.class.php` 定义静态 check、install、uninstall 三个方法；同时提供菜单、路由、模板、优先脚本及原子写入辅助函数。它是插件机制的共享文件，不属于某一个插件。
- `plugin.db` 保存 order、active、idx、ver、name、intro。后台维护记录，应用的 plugin.php 不保存这些状态。不手工把文件内容改成 PHP 或 JSON。
- `allow` 供 myPacker 及 manager 文件扫描使用，按行列出允许项目；不是 PHP 自动加载规则、插件启用清单或 HTTP 访问权限。当前 allow 未列 myBackup，新建 app/Admin 也未列 app/allow；这些清单是现有发布选择，不能用于判断运行时是否可发现项目。

## myBackup

| 原问题 | 修正 |
| --- | --- |
| 用插件连接覆盖全局 `$db`，后续页面或统计落到错误数据库 | 使用独立 `$backupDb`，关闭时不影响框架连接。 |
| 选择“全部数据库”后实际尝试连接名为 all 的库 | 界面明确选择一个数据库，仍支持其全部表；无效数据库提前拒绝。 |
| 任意表名拼入维护 SQL，下载文件名未编码 | 库/表必须来自连接实际列表，标识符统一转义，下载名编码。 |
| 上传失败时 `$result_exe` 未初始化，ZIP 解压失败仍继续读取目录 | 初始化结果并检查解压结果，失败停止。 |
| 不同管理员共用临时目录及同名备份文件 | 每次操作使用随机工作目录，响应结束清理。 |
| 取消导入确认后仅 return，浏览器仍可能提交 | 明确返回 false；校验失败不显示遮罩；导出不留下遮罩。 |
| 切换数据库丢失查询字符串路由 | 使用公共 `queryURL()` 合并参数，保留路由与片段。 |

备份测试只在随机创建的空数据库中读取列表、验证失败分支，结束后删除该测试库；没有向现有库导入 SQL、执行优化或修复。

## badReq

- 解除屏蔽先保存列表再跳转，修复原来的 switch 穿透导致修改未保存。
- 删除按完整 IPv4/IPv6 地址匹配；重置清空记录，保留连接和表结构。写操作必须 POST。
- SQLite 使用绑定参数；最近请求按准确 IP/路径记录，累计计数使用 `SUM(cnt)`，增加 IP/时间索引。首次需要时补齐表结构，不依赖旧安装顺序。
- 计数查询会释放 SQL 构建状态，列表改为复用已生成查询，保留筛选和分组。汇总显示累计次数，而不是日志行数。
- 分页函数移到插件类中，避免与应用的全局函数冲突；修复空数据、越界页和三种路由模式。
- 优先脚本在独立作用域中执行，避免覆盖框架全局变量；支持合法 PATH_INFO/查询路由，过滤空的危险字符配置，每个请求只记录一次。
- Cookie 验证将返回值转换为计数，避免字符串 `"0"` 与数字 `0` 的严格比较差异。屏蔽消息转义输出，跳转只接受无换行的 HTTP(S) URL。
- 表单日志递归脱敏密码、令牌等字段，不保存上传文件正文或临时路径。诊断文件通过受登录保护的插件入口以纯文本读取。
- 屏蔽列表加锁后保存；列表参数、消息及链接按上下文编码，移除影响全站 Ajax 的全局配置。

该插件仍采用现有的简单请求规则。日志记录的 30 秒累计属于近期聚合，并非每次请求独立时间戳的严格滑动窗口。

## frontend

- JSON 同时兼容正常格式和历史多余反斜线；保存前校验应用、jQuery、Bootstrap 版本和文件是否存在。非法输入不覆盖配置。
- 启动钩子明确读取 `info_app`，不依赖别名变量 `I` 是否可用。
- jQuery 3.x 使用 Migrate 3.4.0，1.9–2.x 使用 Migrate 1.4.1，1.9 以前不额外加载迁移脚本。
- Bootstrap 优先使用 bundle，2/3 没有 bundle 时使用实际存在的 bootstrap.js。
- 配置 JSON 从转义后的 textarea 读取，不再拼入 JavaScript 字符串；动态表格使用 `.text()` 写文本。

各版本的库文件保留原样。跨 Bootstrap 主版本切换仍需应用自身的模板与组件代码兼容，不能仅替换资源文件。

## memcached

- 正常存储 `0、false、null、空字符串、空数组`，只有省略 value 参数才按旧约定删除。
- 实现 `interface_cache_lookup::fetch($key, &$hit)`，区分有效 false/null 与未命中；正常未命中不触发 PHP 错误。
- 服务器配置支持字符串、IPv6 括号地址、位置数组、关联数组、列表和正常/旧格式 JSON，不依赖字段顺序。
- `timeout` 按秒转换为 Memcached 毫秒；持久连接兼容 `persistent` 和旧拼写 `persistant`，连接池按服务和超时配置隔离。
- 长键转换为固定长度协议键；插件入口默认按框架目录隔离命名空间。键格式升级后旧缓存自然过期，新请求按冷缓存处理。
- 超过 30 天的 TTL 转绝对到期时间，非法或溢出的时间明确报错；关闭连接使用原生 `quit()`。
- 替换缓存后继续同步框架数据库的查询缓存引用。

`clear()` 和兼容入口 `clean()` 仍是管理员显式清空整个 Memcached 服务的操作，包括其他命名空间；初始化不会调用。测试使用协议替身，未连接或清空真实共享服务。

## manager

- 管理入口和打包入口补充登录检查；与公共 CSRF 桥接同步保护写操作。
- 更新地址默认 HTTPS，并拒绝显式 HTTP、URL 凭据、查询串、片段及控制字符。原来仅支持 HTTP 的更新源需提供可信 HTTPS 地址。
- 下载更新先限制解压大小、禁止反序列化实例化对象，并校验四类数据结构、索引、内容类型、重复成员和全部目标路径，然后才落盘。内容 `"0"` 不再误判为删除。
- 文件名和包标识校验阻止目录穿越；目标解析拒绝符号链接。差异下载只处理已发布清单中的文件，排除配置口令、会话/缓存、上传文件和屏蔽列表等私有成员。
- 远端清单比较直接接收清单，不临时覆盖本地基线文件；校验扫描跳过符号链接和忽略目录，兼容真实路径中的系统符号链接。
- 配置导出从根节点逐个定位密码，清空导出副本中的密码，不修改原配置，跳过结构中的 func 元数据。
- 打包不再临时移动在线菜单，而是在生成归档内流式替换默认菜单；移除对已经删除的 enphp 组件的调用，安装脚本保留为普通 PHP。打包失败明确提示。
- ZIP 上传使用随机目录，检查解压结果并预检成员；更新前备份已有文件，包括将删除的文件。下载、版本查询等参数补齐缺省值。

更新包里的 PHP 配置/迁移代码属于更新机制的既有能力，仍要求来源受信。此轮没有连接真实远程更新源或执行热更新，也未引入更新包签名协议；HTTPS、结构校验及路径边界不等于完整的供应链验证或整站事务回滚。

### 独立安装模板

`manager/install.php` 在已安装网站内直接访问会拒绝执行。解包类先校验整个成员目录和文件长度，再写文件；拒绝穿越、绝对路径、反斜线、符号链接、重复成员和截断数据，限制压缩/展开大小及成员数。修复误删文件结尾 `dir/fil` 字节的问题，保留二进制内容和零长度文件。

失败保留原压缩包；成功按临时文件替换输出，减少文件半写状态。安装/清理使用会话令牌和 POST，浏览安装页不先删除 .htaccess，复查时不覆盖已有安装脚本。

测试只提取解包类，或在带标记配置的临时目录验证拒绝执行；没有对现有网站运行安装流程。完整新站安装和真实更新失败恢复仍需在独立部署副本中演练。

## sample

- 公开模块仅显示对象类名，避免转储控制器、设置及数据库连接的内部凭据，展示内容进行 HTML 转义。
- 限流使用独立 `sample_counter` Cookie，固定 60 秒窗口，不再与 Sample 应用的路由演示共用 `counter`。管理员的 `sysop === 'y'` 豁免保留；超过次数返回 429 与 Retry-After。
- Cookie 计数仍属于演示功能，不能替代服务端限流。模板示例缺少 attr 时使用空默认值。

## 现有共享调用的请求保护

- `showPluginPage()` 在登录检查失败后立即停止，不继续加载插件模块。插件标识、模板页名和目录校验阻止路径穿越；框架后台插件管理入口也在任何脚本包含前校验 `idx`。
- 菜单安装保持幂等，卸载删除全部匹配项；旁路锁覆盖菜单读改写，格式错误时保留原文件。空菜单的后台路径从真正的框架配置读取。
- 模块已经生成 `content` 时复用结果，避免二次渲染。
- `pluginQueryURL()` 保留片段及 `index.php?路由`，统一编码查询参数。
- `mySecurity` 与 `security.js` 同步识别插件写操作：更新管理器的 build/check/empty/upload/download/plugin/app/pack、框架打包，以及 badReq 的 ban/unban/del/reset。服务器要求 POST，浏览器端的旧链接和 jQuery 请求自动转换为 POST 并携带 CSRF；读取列表和本地/远端校验比较继续使用 GET。

## 后续边界与验证

执行顺序、active 与显式路由／priority 的区别、注册表长度和下划线标识限制，以 [插件规范](../../plugin/README.md) 为准。停用不等于卸载，发布 allow 与运行发现范围也不是同一清单。验证命令见 [测试说明](../../tests/README.md)；本次不执行真实插件的安装、更新、卸载或恢复。

### 本轮验证边界

测试只使用临时配置、临时注册表、协议替身及随机空数据库；没有改变线上插件启用状态、运行远程热更新、导入现有业务库、清空真实 Memcached 或重建 check_* 发布资料。memcached 键布局升级会使新请求按冷缓存处理；旧键等待原 TTL 到期，长期不过期的旧键需要运维另行安排清理。

源码审查和这些回归不等于穷举全部数据库版本、第三方组件主版本组合或更新迁移脚本。真实热更新与完整安装仍需在独立部署副本中演练。新的通用要求见 [插件编写规范](../../plugin/README.md#12-本轮审查形成的编码要求)。
