## 13. 域名绑定

域名可以绑定应用或虚拟路由前缀，URL 生成器依据当前上下文处理前缀，实际请求仍由同一框架调度。配置只保存主机映射，DNS、证书、Web 站点和 PHP 版本由部署环境负责。

API 专属域名在框架 API 参数中设置；留空使用普通路径，非空提供该主机的虚拟 API 入口，原 `/api/...` 仍可用。它不会自动共享不同应用／主机的会话，也不会自动开启接口跨域。

不要在通用代码中写死本机 `mystep.com` 或某个后台域名。本机实际资料单列于[站点部署](../../basics/01-guide-basics.md)，不属于 Hello 的开发要求。

## 操作步骤与注意事项

本功能源码全部放在自己的app目录。同名核心继承myStep，module与template按功能对应。JS代码另按JavaScript前端专栏编写；应用入口不再次启动框架或Session。

## 绑定值与访问路径示例

```php
// config/domain.php的示意内容；真实保存使用既有域名绑定后台。
return ['hello.example.test'=>'Hello'];
```

普通站点的`/Hello/detail?id=7`在绑定主机上可按应用虚拟前缀解释为`/detail?id=7`。Host解析去端口并统一小写；DNS、Web虚拟主机和证书必须另行配置。绑定不会自动提供登录权限或跨站Cookie。

`URL_FIX`是条件常量；访问普通主机时可能不存在，不能在应用里无条件拼接。`setURL()`按当前模式与绑定生成地址，`checkBind()`仅在设置与绑定表条件满足时跳到绑定主机。

测试要覆盖：绑定主机首页、子页面、查询串、应用资源、普通路径入口，以及专属API主机冲突。API域名在框架api配置分组单独设置，见[API专属域名](../../backend/api/api-domains.md)。
