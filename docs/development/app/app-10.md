## 10. 缓存系统

先区分可共享和用户专属数据，确定业务键与语言、站点、权限等维度，再选择数据或页面缓存。用户页默认谨慎开启 HTML 缓存；公共列表可以缓存经授权筛选后的稳定数据。

使用 `fetch()` 的命中标志区分 false/null 值；并发计算用可选锁能力而不是不加判断地抢写文件。更新数据库后同步考虑有关缓存失效；不要缓存一个带连接状态、流资源或闭包的整个应用对象。

缓存清理范围及驱动行为见[缓存专题](../../backend/README.md)。新旧后台提供的全量清理是已定义区域的管理操作，不是允许应用随意删除 `cache/` 中的会话和活动锁文件。


## 操作步骤与注意事项

本功能源码全部放在自己的app目录。同名核心继承myStep，module与template按功能对应。JS代码另按JavaScript前端专栏编写；应用入口不再次启动框架或Session。

## 缓存的数据与范围

| 层次 | 保存内容 | 失效条件 |
| --- | --- | --- |
| 模板编译 | 模板生成的受信PHP代码 | 模板／依赖内容变化 |
| 页面缓存 | 已渲染HTML | 页面TTL、显式删除、vary维度 |
| 通用缓存 | 应用计算结果 | 业务TTL或写操作删除 |
| 数据库查询缓存 | 驱动相关查询结果 | 写入及配置的失效规则 |

```php
// 当前应用已获得$cache；键中写明应用和数据维度。
$key = 'Hello:public:summary:v1';
$cache->set($key, ['count'=>0], 60);
$summary = $cache->fetch($key, $hit);
if (!$hit) $summary = ['count'=>0];
assert(is_array($summary));
```

命中标记区分有效false/null与未命中；后台权限、用户菜单和CSRF不能共用无隔离页面缓存。用户／租户差异应进入vary或缓存键；写操作成功后清理实际受影响内容。不要仅依赖end钩子执行失效，因为下载/API可能提前结束。更多见[缓存](../../backend/cache/cache.md)、[模板缓存](../../backend/templates/template-cache.md)。
