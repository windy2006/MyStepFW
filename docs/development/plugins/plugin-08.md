## 8. 实战：编辑器扩展

当前 vendor 中的编辑器及其他组件按照已有保留决定使用。插件只在需要编辑器的页面加载相应本地资源，在模板提供明确的 textarea／容器，并在页面与配置就绪后初始化。不要为了一个编辑页让所有 API、下载和后台首页都加载编辑器。

编辑器按钮和字段规则使用应用／插件的语言及配置结构；表单基础合法性仍由 checkForm 统一处理。编辑器客户端可生成富文本，但服务端仍需决定允许的 HTML、上传类型、资源归属和保存权限；HTML 输出转义规则不能由“编辑器生成的”几个字替代。

插件自己新增的第三方资源保存在本插件目录，并按许可证及发布清单维护；已有通用 vendor 不重复复制多个版本。具体依赖用途见[依赖与组件](../../basics/02-installation.md)。


## 操作步骤与注意事项

index.php中的$this是当前宿主控制器；class.php声明plugin_标识。设置、语言和资源均显式加载，独立入口不自动获得管理员权限。JS初始化代码放入前端脚本，后端负责数据和授权。

## 后端登记编辑器扩展

```php
// plugin/hello/index.php；调用时当前宿主支持myStep编辑器功能。
// JavaScript文件内容由下一篇前端示例给出，仅限受信插件源码。
$this->editorSetPlugin(PLUGIN.'hello/asset/editor-extension.js', 'hello_button');
```

| 方法 | 参数与行为 | 返回／限制 |
| --- | --- | --- |
| `editorSetPlugin($code, $btn='')` | code可为受信JS文本或本地文件；btn为工具栏项 | 返回当前控制器，仅登记 |
| `editorGetPlugin()` | 按当前应用组合登记的代码和按钮 | 返回当前控制器，生成cache/script/editor_plugin_应用.js；已有缓存时复用 |

现有缓存生成按当前实现复用已存在文件；插件扩展代码或按钮变化后应通过缓存管理清理对应编辑器缓存再生成。不能把普通用户输入当作code，也不能把本地文件不存在的路径误当有效脚本。

编辑器容器、脚本加载和按钮JS见[编辑器初始化与插件按钮](../../frontend/javascript/js-editor.md)。此处只介绍PHP登记过程。富文本存储前由服务端按业务策略过滤，上传接口单独鉴权并限制类型。
