# 顺序、优先脚本、宿主布局与升级

修订日期：2026-10-23。适用于当前框架。

## 本篇目标与调用场景

以hello为教学标识，区分生命周期、普通宿主初始化、独立路由/API与优先脚本。

## 7. 重要补充：顺序、优先脚本和后台宿主

### 7.1 顺序与启停

活动插件按 order 从大到小执行，相同值保持原注册顺序；普通宿主初始化与应用绑定求交集并去重。前置脚本也使用活动插件顺序，但有效应用前置脚本先于插件前置脚本，不参与插件 order 排序。

启停应影响新的初始化、路由及优先执行判断。禁用不等于立即删除插件目录或已复制的前置文件；卸载时仍执行相应清理。不要通过改变应用绑定数组的重复次序代替全局运行顺序。

### 7.2 已实施的优先脚本

插件安装时显式调用 `setPriority('hello')`，将自身 `priority.php` 安装到 `config/priority/plugin_hello.php`。运行时 `go()` 在常规应用、会话及认证准备前，检查来源、元信息、注册状态后执行。badReq 的早期检查使用这条机制，不能改成普通 page／start 钩子而声称优先级相同。

复制后脚本的 `__DIR__` 指向配置目录，访问原插件应使用 `PLUGIN.'hello/'`。此阶段不假定 `$this`、当前应用 `PATH` 或登录信息已就绪。前置脚本来源是受信代码，不作为执行用户提交 PHP 的入口。

### 7.3 通用后台布局

需要管理页的插件使用通用插件页面机制，宿主根据允许的应用信息及来源确定；来源为空时默认 myStep，不能把任意 Referer 当作可加载的模板路径。Admin、myStep 和符合约定的应用可提供自己的 `plugin_layout.php`／相应适配，插件保留自己的主体模板。

Referer 只帮助选择外观，管理员校验、CSRF 和业务权限单独执行。页面内表单、返回链接及 AJAX 地址使用 `pluginPageURL()`／`pluginAdminURL()` 等现有辅助入口，避免切换宿主后又跳回固定旧后台。详见[插件规范](README.md)的后台通用布局部分。

### 7.4 打包、升级与失败反馈

统一包安装流程先预检路径与资源、检查权限，经过暂存再替换，并提供失败反馈和相应回滚。正常的很小归档也可能有效，不用固定“至少1KB”判断完整性。

旧更新站点不作为本地测试依赖；manager 与插件升级夹具以当前代码为基线，使用临时模拟源验证版本判断、在线／离线升级、系统打包和解包。不对正式站点执行升级来检查教程；配置、数据库和业务文件要按包规则保留。

网站文件由 PHP 创建有助于后续维护，但仍受所有者、目录权限、ACL、挂载与部署策略影响。不能把框架的权限预检或失败回滚描述为所有系统上的任意删改能力。


## 操作步骤与注意事项

index.php中的$this是当前宿主控制器；class.php声明plugin_标识。设置、语言和资源均显式加载，独立入口不自动获得管理员权限。JS初始化代码放入前端脚本，后端负责数据和授权。

## 主要方法：参数、返回和失败约定

### setPriority

功能说明：将插件 priority.php 原子复制到框架优先脚本目录，覆盖旧版本。

目标为 CONFIG/priority/plugin_插件标识.php；源文件复制后 __DIR__ 会改变，
引用插件资源须使用 PLUGIN 常量。调用本函数不会立即执行优先脚本。

```text
function setPriority($idx);
```

| 参数说明 |
| --- |
| string $idx 已存在的插件目录名 |

**返回**：bool 安装成功为 true；没有 priority.php 时为 false

**异常**：InvalidArgumentException 插件标识/目录非法，或源脚本为符号链接；RuntimeException 无法读取、创建或完整发布脚本

### removePriority

功能说明：删除插件优先脚本并使 OPcache 失效，支持目录已删除和重复清理。

```text
function removePriority($idx);
```

| 参数说明 |
| --- |
| string $idx 插件目录名；只用于构造配置文件名，不读取插件目录 |

**返回**：bool 删除成功或脚本原本不存在时为 true

**异常**：InvalidArgumentException 插件标识非法；RuntimeException 目标异常地成为目录，或无法删除目标文件

## 两种顺序机制和执行前提

| 机制 | 运行阶段 | 上下文 | 适合工作 |
| --- | --- | --- | --- |
| plugin.db的order | 普通应用插件初始化 | 当前宿主已经选定 | 登记钩子、模块和页面资源 |
| config/priority中的优先脚本 | go较早阶段 | 尚无普通应用会话、模板或数据库保证 | 轻量请求预检／拦截 |

```php
// 管理员安装流程中的辅助调用；登记的源文件必须真实存在。
if (!setPriority('hello')) {
    throw new RuntimeException('优先脚本登记失败');
}
// 卸载时清理对应登记，而不是删除其他插件的优先项。
removePriority('hello');
```

实际setPriority的参数及返回契约见[插件共享接口](reference/interface-plugin.md)；安装文件应检查它是否成功，不把注册普通插件当成优先脚本已安装。不要在优先脚本连接业务数据库、读取管理员Session或构造页面。

升级涉及权限预检、包成员限制、暂存和发布，不能直接用解包成功代替整站升级完成。主服务器检测和离线升级见[manager插件](../../showcase/plugins/manager.md)。
