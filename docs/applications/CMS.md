# CMS 应用、链接与配套调用

整理日期：2026-10-18。目标运行环境：PHP 7.4。同类内容合并，以较新的应用维护说明覆盖早期结论；下列修复记录不等于本次重新执行业务操作。

## 栏目、内容、标签与统计

| 问题 | 修正与当前约定 |
| --- | --- |
| 栏目构树依赖父级编号较小，反复线性查找父级；孤儿和循环关系处理不可靠 | `categoryTree()` 先建立编号索引，按实际父子关系构树，再排序兄弟节点。孤儿、自指和环在内存中断为根节点，不自动修改数据库记录。 |
| 面包屑和侧栏可能循环寻找父级，缺失父级时读取无效数组 | `categoryPath()` 统一检查缺失节点和环，文章、栏目及侧栏同步使用。 |
| 后台可提交自身/后代作为父栏目 | 写入前校验父级路径、所属网站和网站权限；非法关系提前停止。 |
| 搜索多页正文造成同一文章重复；标题和正文搜索条件与总数统计不一致 | `buildSQL()` 通过 `EXISTS` 搜索正文，保留标题匹配，每篇文章只返回一条；栏目、标签、搜索的总数复用列表查询规则。栏目索引使用 `cat_idx` 别名，避免派生计数查询出现重名字段。 |
| 分页允许负数或超出末页；未选栏目时读取 `false['cat_id']` | 前台复用 `getPageList()` 的边界处理；栏目为空时跳过自定义模板查找。 |
| 标签长度判断误写为 `strlen($tag > 50)`；含数字的有效标签被删，文章添加与重建的截断规则不同 | `normalizeTags()` 统一分隔符、去空值、按文章去重、最多保留 50 个 UTF-8 字符。只排除全部由数字/点组成的标签，保留 `PHP7`、单字中文和引号。文章添加及重建同步使用。 |
| 标签删除/重建拼接标签到 SQL，存在引号错误和误删边界；删除单标签不完整 | 数据值采用参数绑定；删除按完整标签处理，兼容单独出现及相邻重复项。文章新增标签去掉手工 `safeValue()`，避免双重转义。 |
| 重建标签逐个执行文章表的 LIKE 统计，结果把子串当完整标签 | 单次读取文章标签，在内存中按完整标签统计每篇文章的贡献，保留现有标签点击数和添加时间，删除不再使用的标签。 |
| 统计先读取计数再覆盖，多个请求会互相覆盖 | 使用单条 `INSERT ... ON DUPLICATE KEY UPDATE` 原子增加 PV/IV，并取在线峰值；保留现有 MyISAM 表兼容性。IV 对同一访客的判定仍沿用现有 Cookie/IP 规则。 |
| 空验证码与空会话验证码可能相等；个人资料密码 `"0"` 被当空值忽略 | 验证码必须双方都是非空字符串；密码更新使用严格空字符串判断并拒绝数组输入。注册写入失败时不建立登录状态。 |
| 文章 60 天锁定判断把秒时间戳除以 1000，规则失效 | 统一按秒比较；超过 60 天的文章需先使用原有“解锁”操作，POST/CSRF 保护继续生效。 |
| 备份上传失败时结果数组未初始化；表名直接拼进维护 SQL | 初始化结果；导出、优化、修复的表名必须在实际表列表中，标识符统一转义。 |

标签重建是显式的管理操作，本轮没有在现有业务库执行。当前实现一次读取文章的编号和标签，避免反复全表扫描；特别大的文章库仍可进一步改为分批遍历。表引擎、标签唯一索引和批量写入事务的迁移未在本轮调整。

栏目衍生缓存 `cache/app/CMS/news_cat.php` 已备份后失效，并通过正常页面请求重新生成。

本次针对日常 CMS 前台与后台页面检查了模板的 href/action/src、JavaScript 跳转与 Ajax 地址、分页及保存后的跳转。兼容 PHP 7.4，不改变现有路由语法和权限/CSRF 约定。

### 已修复的问题

| 位置 | 原问题 | 修复方式 |
| --- | --- | --- |
| 公共 `static/js/global.js::setURL` | 无条件将 `?` 改成 `&`，并对包含查询值的整个链接压缩斜杠 | 使用 `routeURL` 分离路径和查询；仅查询串路由使用 `&`，参数、锚点和完整 URL 保持原样 |
| 文章、友情链接、自定义内容添加 | 生成 `add&cat_id=...` 或 `add/&web_id=...` | 保留模板中正确的问号，修复公共转换过程 |
| 文章修改、删除、解锁 | 模板直接写成 `edit&web_id=...` 等旧式路径 | 改为标准 `edit?web_id=...` 等链接 |
| 模板管理 | 列表、添加、编辑、导出、删除、模板切换使用旧式 `&idx=` | 统一标准查询串，对模板索引及文件名分别编码 |
| 后台各列表搜索、筛选、排序 | 搜索词及索引包含 `& + # ?` 等字符时参数被截断；切换栏目丢失子站 | PHP 使用 RFC 3986 编码，模板使用 `|url`，JS 使用 `queryURL`；切换栏目/链接索引保留所选子站 |
| CMS 公共分页 | 从 REQUEST 的第一个键推测路由，依赖参数顺序；翻页丢失筛选条件 | 根据已解析的当前模块生成 URL，保留筛选参数并覆盖页码；空记录及越界页归入有效范围 |
| 筛选上下文 | 文章分页误用文章 ID 作为栏目 ID；友情链接分页误用当前域名子站 ID，遗漏索引；管理员分页遗漏群组 | 改用实际选择的栏目、子站、索引及群组 |
| 前台文章多页 | 使用 `&page=`，查询串模式还会删掉整个文章路由 | 根据当前模块路径重新生成 `?page=` 或查询串路由形式 |
| 前台栏目、标签 | 路径中标签未编码；栏目解码后再次将加号换为空格 | 路径段使用 `rawurlencode`，读取时只解码一次，兼容旧链接的加号空格约定 |
| 前台搜索表单 | 查询串模式下原生 GET 提交覆盖 action 查询串，丢失搜索路由 | `setURL` 给该模式的 GET 表单添加提交处理，保留路由首段并合并编码后的字段 |
| 前后台验证码 | `captcha/&core=CMS&` 地址错误，刷新反复追加时间戳 | PHP 生成完整验证码地址；刷新覆盖 `t` 参数 |
| 后台保存/返回 | 通过正则删除 REQUEST_URI 末尾动作，有参数或尾斜杠时失败；无 Referer 时返回空地址 | 生成固定模块列表地址；直接访问输入页时提供返回列表的默认值，返回按钮通过 HTML 属性读取 URL |
| 后台框架与侧栏 | iframe 从完整当前 URL 追加 `/info`；侧栏旧参数拼接、子站链接固定 HTTP | 由模板直接输出服务端生成的后台首页 iframe 地址，不依赖异步 setting；避免初始化异常同时阻断侧栏箭头事件。栏目/子站参数编码，子站地址使用协议相对形式 |
| API 调用 | 上传参数和文章标题直接拼接，查询串模式或特殊标题可能截断 | 查询参数使用 `queryURL`，分词标题使用 `encodeURIComponent` |
| 日志链接 | 为没有问号的地址追加 `&id=`，完整 URL 再解码导致分隔符失真 | 合并编码参数并保留编码后的原链接 |
| RSS、Atom、站点地图 | 主机名直接拼接跨站 `//host/path`，订阅入口与图标忽略应用/子目录 | 使用绝对 URL 生成器，并区分 XML 属性转义和 CDATA 中的原始 URL |
| 编辑器及公共资源 | 多处 static/vendor 路径写死根目录，编辑器插件文件名大小写与生成器不一致 | 使用部署根目录或应用路径，插件脚本采用实际应用标识拼接 |
| 框架 PATH_INFO 前缀 | 空路径生成 `index.php`，后续拼接得到 `index.phpcaptcha` 等地址 | 空路径返回 `index.php/`；其他模式保持原约定 |

### 链接编写约定

模板中使用 `add?web_id=<!--web_id-->`，由 `setURL` 按当前模式处理。不要写 `add&web_id=...`。用户输入和文件名放入查询值时使用 `<!--keyword|url-->`；显示在 HTML 属性中使用 `|html`。

JavaScript 的直接跳转和 Ajax 不经过 DOM 链接扫描，应调用：

```js
location.href = queryURL(global.root_fix, {web_id: '2', keyword: input.value});
location.href = queryURL(routeURL('list'), {idx: templateName});
const uploadURL = queryURL(setting.url_prefix + 'api/myStep/upload', {core: 'CMS'});
```

CMS PHP 端提供以下函数（均位于 `app/CMS/lib.php`）：

```php
// null 路径代表当前已经解析的 CMS 模块，查询值由函数统一编码。
$url = \app\CMS\getURL('admin_cms/article/content/add', ['cat_id' => '', 'web_id' => 1]);
$url = \app\CMS\queryURL($url, ['cat_id' => 5]);
$url = \app\CMS\absoluteURL($url); // 订阅/站点地图使用
```

实际后台目录应读取 `$S->web->path_admin`。HTML 输出时再按属性或文本上下文转义；不要提前对参数做 HTML 转义，也不要对已经生成的完整 URL 再做 urlencode。

### 验证

```sh
php tests/applications/cms_link_regression.php
CMS_LINK_BASE=/sub/ php tests/applications/cms_link_regression.php
CMS_LINK_BOUND=0 php tests/applications/cms_link_regression.php
CMS_LINK_BOUND=0 CMS_LINK_BASE=/sub/ php tests/applications/cms_link_regression.php
node tests/applications/cms_link_browser.js
```

PHP 专项覆盖根目录/子目录、绑定/未绑定域名及三种路由模式，直接调用框架路由解析器及 CMS URL 函数。Node 专项读取实际 CMS 模板的 PHP 渲染结果，并执行真实公共链接函数，检查地址转换、重复转换、添加入口、特殊字符和查询串搜索表单提交。此专项不访问数据库，也不执行正式文章/链接/模板的增删改。

HTTPS 验证访问实际 CMS 后台列表、两个添加表单、模板列表、前台栏目/搜索/标签及订阅入口；没有提交正式业务表单或执行删除/解锁动作。安装器不属于日常前后台流程，本次未执行安装或调整安装引导。

本次验证结果：PHP 7.4 专项 72 项、真实模板 JavaScript 专项 725 项通过；现有 717 项 PHP 回归、26 项 JavaScript 检查和 11 项本机 I/O 场景通过。线上以本机 HTTPS 访问 42 个前后台页面及 19 个页面资源均成功，相关请求没有新增 error.log 内容；另有框架原有 47 次 HTTPS 冒烟检查通过。页面输入表单只验证渲染和目标地址，没有向正式数据库提交新增或修改。

## 模板缓存与 XML 入口

检查 Atom、RSS 和 sitemap 的页面缓存命中路径时，发现三个 CMS XML 入口在应用配置合并、数据库选择之前调用 `checkCache` 并结束请求；随后结束统计会查询到基础库中不存在的 CMS 表。已把配置合并和数据库选择移到缓存分支之前。三个入口均增加独立进程回归，实站分别验证首次生成和缓存命中，XML 能正常解析。

## 图片、附件及前端适配

文章导入远程图片使用 importPublicImage：只接受可识别并可解码的 JPG／PNG／GIF，重新编码后保存，按内容决定扩展；失败不追加日志或替换 URL，GIF 静态保存。公开 URL 校验统一见 [通用工具](../framework/utilities.md)。附件定位使用 myAttachment，图片按真实扩展识别。

CMS 的密码确认参数由后端验证并在写库前移除，旧页面不发送确认字段仍兼容，字符串密码 0 可更新。前端 checkForm 不能代替该检查。

guide 主题设计原型的 syntaxhighlighter 引用已改为 vendor/highlight/syntaxhighlighter，补齐 XRegExp；实际主题的脚本仍归应用 asset。

## 安装和后续专项

本轮没有对现有业务库执行安装、导入恢复、删除文章或标签重建。CMS 旧安装器仍有预加载阶段资源初始化和硬编码资源/跳转路径的问题，应在独立目录和空数据库中单独调整并演练完整安装；不能用现有业务库作安装测试。

## 数据缓存配套调用

栏目删除、排序、编辑及文章建栏目的函数缓存删除统一传 TTL 0；getData_func 保留历史 null 删除约定。文章查询显式传入 all 模式及 1 秒 TTL，避免把参数 1 误认为读取模式。共享驱动清理和事务缓存规则见 [缓存](../framework/cache.md)。
