# 框架设置（myStep） <small>v1.4.0</small>

## 功能概述

提供框架的原管理后台及通用路由入口。后台包含运行信息、配置、类加载、域名、应用、插件、API、缓存、附件、语言、前端示例和开发指南；本目录的路由还声明验证码、公开浏览器设置、语言、文件和API等框架入口。

应用名为`myStep`，框架执行核心在网站根`lib/myStep.class.php`。本目录的管理页面和模板是其后台应用部分；不需要在本目录复制一个同名核心文件。

## 安装与访问

使用框架当前运行环境：PHP >=8.5.12 且 <9。本文中的目录均从网站根计算，所需数据库、图片或存储扩展按具体功能准备。

1. 在完整框架内保留`app/myStep/`；通用路由和其他后台也会复用本应用的公共声明与资源。
2. 使用配置`gen.path_admin`对应的逻辑路径进入，默认示例为`console/`。访问`myStep/`也会跳转到该后台入口。
3. 使用框架管理员账号、密码和验证码登录。
4. 在“参数设置”中选择主框架或本应用，分别维护全局配置和后台界面参数。

不要把`gen.path_admin`、应用目录`myStep`、新后台`Admin`和CMS后台路径混为一个设置。网页地址通过框架URL方法生成；以下是默认后台路径的例子：

```php
$url = myStep::setURL('console/function/app');
```

后台路径经过修改时，把例子中的`console`换为实际配置值。实际运行中可从已初始化的`$ms_setting->gen->path_admin`取得。

### 应用管理

应用名称旁的“说明”打开当前应用自己的README，不混入框架指南。插件关联只列出已安装且启用的插件；保存可修改当前可见选择，停用插件的已有绑定保留，待重新启用后再显示。若插件状态在另一窗口改变，刷新应用管理后再保存。

在应用条目下编辑`route.php`源码，点击“插件”选择该应用要调用的插件。最终使用“更新路由及插件设置”保存；只勾选浮层中的选项还未写入应用文件。

“路由扩展”填写PHP返回数组，键是来源标识，值是网站根相对路径，例如：

```php
<?php
return array (
    'custom' => 'app/Hello/config/extra_routes.php',
);
```

自定义文件按框架规则提供`$rule`、`$format`或`$api`。不要直接编辑生成的`config/route.php`。配置源的写法见[路由规则](../../docs/backend/routing/routing.md)。

### 配置和语言

主框架参数保存在网站根`config/config.php`，本应用参数保存在`app/myStep/config.php`，其他应用保存在各自目录；选择目标后再保存。应用语言在对应应用的`language/`下维护；页面选择的语言和配置结构的语言文件各自负责显示内容与设置字段描述。

### 通用入口

| 逻辑路径 | 用途 |
| --- | --- |
| `captcha/` | 验证码图片 |
| `ms_csrf` | 获取当前会话的CSRF凭证 |
| `ms_setting/应用名` | 输出经过公开白名单处理的浏览器设置 |
| `ms_language/应用名/语种` | 输出相应应用的浏览器语言 |
| `api/应用名/接口名` | 按API管理策略分派已登记接口 |
| `module/应用名/模块名` | 分派已注册模块，不直接执行任意磁盘文件 |
| `sitemap`、`rss`、`atom` | 交由当前应用提供对应功能文件 |

是否可访问及响应格式由具体入口和策略决定。API全局启用、默认响应格式、正文上限和专属域名在主框架“API设置”维护，逐接口设置在“API管理”维护；不是本应用下面这组界面参数。

## 设置说明

以下设置通过本应用的`config/chs.php`描述，保存在`app/myStep/config.php`；没有单独覆盖的项目继承主框架。示例不含真实账号或口令。

### setting-gen-cache_page

**页面缓存**（`gen.cache_page`）

是否缓存当前后台生成的页面。管理内容依赖登录状态和实时数据，通常保持关闭；本项控制页面缓存，不等同于清理数据缓存或静态资源合并缓存。

示例：

```text
false
```

### setting-gen-path_admin

**后台路径**（`gen.path_admin`）

原框架后台的逻辑入口名称，不带域名、前后斜杠或查询参数。通过后台“参数设置”修改并保存，使相关路由同步；此设置不改变Admin应用的独立入口。

示例：

```text
console
```

### setting-web-title

**网站名称**（`web.title`）

显示在当前后台浏览器标题中，不修改其他应用的网站名称。可填写便于区分站点的短名称。

示例：

```text
网站管理后台
```

### setting-web-minify

**页面压缩**（`web.minify`）

控制当前应用输出时的HTML及相关资源压缩。开启后仍通过框架既有资源流程生成；调试模板和脚本时可关闭。

示例：

```text
false
```

### setting-template-name

**调用模板**（`template.name`）

主模板的文件名，不带.tpl扩展名。页面主体由各功能模块自己的模板生成，通常保留main。

示例：

```text
main
```

### setting-template-path

**模板路径**（`template.path`）

相对于网站根的模板目录，不填服务器绝对路径或浏览器URL。程序在运行时与ROOT组合为磁盘路径。

示例：

```text
app/myStep/template
```

### setting-template-style

**模板样式**（`template.style`）

模板目录下的风格子目录名。目录直接存放模板时留空；使用子目录风格时填写实际目录名。

示例：

```text
留空
```

### setting-db-auto

**自动连接**（`db.auto`）

是否在当前后台启动时自动连接框架配置的业务数据库。关闭不阻止特定功能按需连接；“数据库信息”等功能仍需要有效的数据库配置。

示例：

```text
true
```

## 目录与扩展

| 位置 | 用途 |
| --- | --- |
| `route.php` | 框架通用入口与后台路径声明 |
| `index.php` | 将默认应用访问跳转到已配置后台路径 |
| `global.php` | 后台公共上下文、导航与权限准备 |
| `lib.php` | 后台辅助函数，以及共用的API管理和指南读取声明 |
| `module/`／`template/` | 逐项对应的后台处理脚本与HTML模板 |
| `menu.json` | 当前后台菜单数据 |
| `sample/` | 前端功能示例 |
| `asset/` | 本地样式、脚本及指南阅读交互 |
| `config/`／`language/` | 配置字段描述及语言内容 |
| `setting_expand.php` | 参数保存后的关联处理 |

增加功能时按module/template对应关系组织；普通应用的业务代码不要移入框架公共lib目录。

## 常见问题

- **后台网址不是console**：在本应用配置中查看`gen.path_admin`，使用实际入口。
- **设置保存到另一个应用**：先核对“选择配置”的目标；全局设置与应用覆盖分别保存。
- **应用关联了插件但没有效果**：插件还须已安装并启用，且当前页面使用了该插件提供的钩子、模块或标签。
- **源码编辑和代码测试**：使用内置CodeMirror；代码测试会在服务器执行输入内容，只输入已核实的可信代码。
