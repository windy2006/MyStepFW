# 简明管理后台（Admin） <small>v1.4.0</small>

## 功能概述

提供框架管理员的集中管理界面：运行信息、数据库浏览、PHP信息、错误日志、参数与语言、类加载与别名、域名绑定、应用、插件、API、缓存、附件、前端示例和开发指南。使用框架现有的路由、Session、管理员认证、CSRF、myTemplate和checkForm；桌面显示侧栏，窄屏使用顶部下拉菜单。

Admin和myStep共用全局管理员账号及框架数据。CMS内容管理、CMS管理员和普通会员由CMS自己的后台管理；不会因登录Admin自动把普通会员变为管理员。

## 安装与访问

使用框架当前运行环境：PHP >=8.5.12 且 <9。本文中的目录均从网站根计算，所需数据库、图片或存储扩展按具体功能准备。

1. 将本应用完整放在`app/Admin/`，保留`Admin.class.php`、模块、模板、配置、语言和asset资源。
2. 在已完成安装的框架中访问逻辑入口`Admin/`；rewrite部署的根目录示例是`/Admin/`。
3. 使用框架参数中配置的管理员账号、密码和验证码登录。未登录时功能页要求先登录。
4. 选择“参数设置 → 简明管理后台”调整本应用；选择“主框架”修改全局参数。

源码路径不能替代应用入口，不直接访问`app/Admin/module/`里的PHP文件。页面链接通过框架生成，支持rewrite、path_info、query_string和子目录部署，例如：

```php
$url = myStep::setURL('Admin/function/app');
```

### 应用与路由

应用名称旁的“说明”打开当前应用自己的README，不混入框架指南。插件关联只列出已安装且启用的插件；保存可修改当前可见选择，停用插件的已有绑定保留，待重新启用后再显示。若插件状态在另一窗口改变，刷新应用管理后再保存。

每个应用单独保存自己的`route.php`和`plugin.php`。路由源码框用于编辑该应用的规则；插件关联用于该应用页面中的插件调用。下方“路由扩展”是额外路由来源的映射，不是插件启用开关：

```php
<?php
return array (
    'custom' => 'app/Hello/config/extra_routes.php',
);
```

先创建源文件，再保存映射；源文件按框架要求定义`$rule`、`$format`或`$api`。文件路径相对于网站根，映射保存在`config/route_plugin.php`。已有外部来源会完整回显，空白清除显式来源；启用插件自己的自动路由不因清空而移除。详细写法见[路由扩展](../../docs/backend/routing/routing.md#后台路由扩展)。

### 源码编辑

代码测试、应用路由、路由扩展和类加载PHP数组使用本地CodeMirror，提供高亮、行号、括号匹配及四空格缩进。Tab缩进、Shift+Tab取消缩进，Ctrl+F11切换全屏，Esc退出；代码测试页可用Ctrl+Enter提交，仍需确认。

保存使用编辑器当前内容，复位恢复打开页面时的内容。配置在其他窗口发生变化时，先重新打开页面再编辑，避免以过期内容覆盖。代码测试在服务器执行可信PHP；只把自己确认的代码放入此工具。

## 设置说明

本应用设置保存在`app/Admin/config.php`；字段结构与显示文字在`app/Admin/config/`。未覆盖的参数继承网站根`config/config.php`，例如管理员账号、Session、数据库连接和邮件配置。以下每项均为示范值。

### setting-gen-cache_page

**页面缓存**（`gen.cache_page`）

是否缓存当前后台生成的页面。管理内容依赖登录状态和实时数据，通常保持关闭；本项控制页面缓存，不等同于清理数据缓存或静态资源合并缓存。

示例：

```text
false
```

### setting-web-title

**网站名称**（`web.title`）

显示在当前后台浏览器标题中，不修改其他应用的网站名称。可填写便于区分站点的短名称。

示例：

```text
网站管理后台
```

### setting-web-minify

**页面压缩**（`web.minify`）

控制当前应用输出时的HTML及相关资源压缩。开启后仍通过框架既有资源流程生成；调试模板和脚本时可关闭。

示例：

```text
false
```

### setting-template-name

**调用模板**（`template.name`）

主模板的文件名，不带.tpl扩展名。页面主体由各功能模块自己的模板生成，通常保留main。

示例：

```text
main
```

### setting-template-path

**模板路径**（`template.path`）

相对于网站根的模板目录，不填服务器绝对路径或浏览器URL。程序在运行时与ROOT组合为磁盘路径。

示例：

```text
app/Admin/template
```

### setting-template-style

**模板样式**（`template.style`）

模板目录下的风格子目录名。目录直接存放模板时留空；使用子目录风格时填写实际目录名。

示例：

```text
default
```

### setting-db-auto

**自动连接**（`db.auto`）

是否在当前后台启动时自动连接框架配置的业务数据库。关闭不阻止特定功能按需连接；“数据库信息”等功能仍需要有效的数据库配置。

示例：

```text
false
```

## 目录与扩展

| 位置 | 用途 |
| --- | --- |
| `Admin.class.php` | 应用核心，继承myStep，处理登录、鉴权、动作和框架输出 |
| `lib.php` | 页面白名单、AdminService模块加载及AdminStore配置保存 |
| `module/info/` | 运行信息、数据库、PHP及日志页面与动作 |
| `module/setting/` | 参数、域名、类加载、别名和代码测试 |
| `module/function/` | 应用、插件、API、缓存、附件和语言管理 |
| `module/guide.php` | 框架指南页面的读取与局部请求 |
| `template/default/` | 对应各模块的HTML模板及复用片段 |
| `asset/` | 当前应用的JS、CSS等本地界面资源 |
| `plugin_layout.php` | 为通过通用接口输出的插件管理页提供Admin布局 |

后台页面和动作放入对应module，HTML放对应template；复用辅助声明放已有`lib.php`，不另在应用根目录添加页面装配文件。默认风格可通过`template.path/style`替换；自定义模板的源码框使用`data-admin-code="php"`，无PHP开头标签的数组使用`data-admin-code="php-array"`。

## 常见问题

- **登录后某个页面仍要求登录**：使用当前站点生成的菜单链接，检查浏览器Cookie、Session存储及域名／HTTPS设置是否一致。
- **数据库页不能读取**：先在主框架配置真实数据库连接；`db.auto=false`只是按需连接，不是数据库地址。
- **修改样式没有变化**：核对当前`template.style`，并在缓存管理中清理相关模板／脚本缓存。
- **插件管理链接没有出现**：先启用插件，确认插件声明了对应后台入口；应用管理员委托权限由插件和宿主共同控制。
